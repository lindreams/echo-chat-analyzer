Echo QQ 完整性现场检查候选 1（基于 v0.2.2，非正式版本）

1. 将整个 ZIP 解压到一个新的、可写的目录，不要覆盖已安装的 Echo。
2. 关闭其他 Echo。双击 Run-QQ-Integrity-Check.cmd。
3. 在打开的 Echo 中按平常流程连接 QQ、完成本机登录，等待会话加载成功或失败。
4. 正常关闭 Echo。命令窗口会显示本次 check-... 目录的位置。
5. 只发送其中的 integrity-result.json；不要发送整个目录、日志、截图或数据库。

无需安装 Python、Node 或开发工具；保留完整的 Echo 子目录。
本候选未证明已解决原故障，目标是一次本机运行取得可直接选择修复路径的固定分类结果。
检查完全在本机执行，不上传聊天数据，不修改 QQ 原始数据库，不绕过 quick_check。
每次启动使用独立的 Echo 设置、运行时工作目录及结果文件；不覆盖正式 v0.2.2 的资产或配置。
正常 QQ 登录仍使用本机 QQ 资料位置。本候选保留原有凭据保护、快照生命周期和明文清理。
新增检查只在内存中对比本次已捕获副本的解密页面，不额外保存数据库、页面、密钥或数据库哈希。
结果只含固定分类、数据库布局数字、主库/WAL 页面一致性计数、校验重试及清理状态。
若 cleanup 为 not_confirmed，原有失败保护继续生效，不要复制或发送任何遗留文件。
若 initial_check 为 not_reached，表示本次运行未取得快照完整性结果，不代表数据库正常或损坏。
check-... 中的 local-app-data 只供本机使用，可能包含正常登录状态和应用日志，不应分享。
不要直接运行 Echo/Echo.exe，否则不会启用本次一次性检查。
