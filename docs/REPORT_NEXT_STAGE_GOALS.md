## 1. 本阶段要解决什么

让报告前段更紧凑，让统计能连接到真实说过的话，并让原文回看成为安静、可选择的小扩展。

当前讨论集中在四个问题：

1. 会话概览和时间节奏分散，少量基础信息占据较大篇幅。
2. 第二章的特别聊天高度重叠，同一轮常同时获得多个标签；没有原文，难以唤起回忆。
3. 成员关键词在超大群之外常显得单薄，缺少“这个词当时怎么说”的入口。
4. 文案的比喻较密，部分标签不够清楚，需要更具体、自然且符合统计依据的表达。

本文汇总本轮讨论，不把所有建议视为已批准的最终设计。实施前仍须核对当时的源码和表情包分支状态。

### 1.1 已明确的目标与约束

- 所有本轮报告改动均在表情包算法完成之后实施。
- 优化已有报告的组织、信息密度和回忆体验，先完成若干小目标。
- 特别聊天需要减少重复，并能看到有上下文的原文。
- 关键词应有查看对应原文的方式；例如“出现在 24 条消息中”应有途径查看这 24 条。
- 默认阅读常用词时不应受干扰：鼠标移过不弹出对话，不自动展开或挤动页面。
- 改善空疏章节和报告文案，同时保留 Echo 的整体视觉气质。
- 记录中的候选不自动获得实施授权；回复关系本轮只审查来源，不插入互动关系或引用回复专题。
- 2026-10-27 确认回复关系分析为群聊专属功能；私聊相关信息仅作为“交流的节奏”的小补充，具体内容另定。后续按场景价值设计，不再要求私聊／群聊机械对标；拍一拍等候选未自动获得实施授权。

### 1.2 工作方案与待验证项

以下保留下一阶段的设计起点；第一章以第 3 节中的最终确认范围为准，其余条目仍是候选：

- 合并现有第 01、03 章；新第一章暂名“交流的节奏”。
- 24 小时表盘与条形图支持点选、滚轮切换与成员切换；本轮不加拖动和方向键快捷键。
- 聊天高光默认最多展示三段不同轮次，同轮合并标签。
- 原文入口按最新确认改为直接点词，打开只读原话面板；成员卡底部统一入口不再作为当前实现。
- 高光默认 6～10 条连续消息；关键词默认预览 3 条，完整列表每次约 10 条。以上数字均可根据样本和阅读效果调整。
- 日／周／月趋势作为同一图表的粒度切换，月均至少覆盖三个完整自然月才出现。
- 最终章节标题、纸面布局、移动端面板形态及大报告体积阈值在实施时确定。

## 3. 目标 A：合并概览与节奏

已实现结构为“交流的节奏 → 聊天轮次 → 语言画像”，后接表达文化、表情包。仅第一章重新排版，后续章节随合并顺延编号。

### 原型审核后的实施范围

- 保留纸面、衬线字与暖色图表；删除第一章的分析范围、消息起止行与正弦装饰，不新增月份统计。
- 表盘／条形切换按钮加大；两种视图均支持点选后用滚轮切换小时，未点选时保留页面滚动。两种视图占位一致，避免切换时挤动页面。
- 不加方向键等导航快捷键，也不保留快捷键展开说明；保留控件自身的标准焦点与激活行为。
- 仅消息最多的小时显示“消息最多的小时”，普通小时不显示“选中的小时”。
- 删除“为什么与会话列表不同？”展开入口，仅在摘要下保留一句静态清洗说明。
- 小时占比以当前对象的有效时间消息为分母；未知时间不归入零点。成员切换不改变全会话摘要。
- 私聊只有身份可靠时显示“你／TA”，否则显示成员名；群聊使用成员选择器。
- 小时图使用已有聚合；星期图按记录跨度内对应星期的天数显示日均，副标题静态显示“约 N 周”，不足一周时显示“不足 1 周”。成员共用同一窗口，未涉及的星期显示“—”。
- 窗口取范围与内容过滤后保留记录的首末日期，称为“记录跨度”，不宣称完整历史覆盖。被忽略消息不影响窗口；新增日均见 DATA_SEMANTICS。

以下内容安排与表盘设想保留讨论背景；日期趋势、拖动、开聊分布等不属于本轮交付。

### 内容安排

| 区域 | 调整 |
| --- | --- |
| 范围 | 显示实际分析覆盖区间、消息起止日期及跨度时，明确彼此含义，不把首末消息跨度误称为完整记录覆盖。 |
| 摘要 | 总消息、参与人数、活跃日、活跃日日均紧凑排列；私聊人数可弱化。 |
| 小时节奏 | 精确刻度、选中小时读数；“最活跃时间”作为图内结论，取消重复的大字段。 |
| 星期节奏 | 周一至周日顺序固定，与小时图并列；窄屏上下排列。 |
| 后续趋势 | 以一张日／周／月可切换图承接日期聚合，避免分别开三页。 |

### 表盘原型

- 24 个小时区段；每 4 小时标主刻度，每小时有细刻度。
- 默认选中有效时间消息最多的小时，显示时间范围、消息数和占比。
- 点击选择小时；尝试拖动指针并按整小时吸附，刻度与文字保持固定。
- 支持明确的键盘选择和可读文字，不能只能靠颜色或拖动读取。
- 私聊尝试“整体／你／TA”，群聊尝试“整体／选择成员”；依赖可靠身份。
- 可将“消息分布／开聊分布”放在同一区域切换，单位分别为消息数与轮次数，说明不能混用。私聊现有基础与群聊完整分布不同，需要分别核对。
- 打印、截图和默认状态保留完整分布与高峰信息，不要求先操作才有主要结论。
- 条形图仍是可比较的备选方案；是否保留双视图由原型决定，不为同一数据无条件同时铺两图。

## 4. 目标 B：把特别聊天做成原文回忆卡

**2026-10-27 决定：暂停本节，留到 0.4.0。** 长轮次片段的代表性与篇幅先不实施；
语言画像的词语原话独立推进，不以通用高光平台作为前置条件。

### 高光去重

- 同一轮只展示一张卡，可同时带“消息最多”“聊得最久”“消息最密集”等标签。
- 暂以最多三段不同聊天为默认；数据不足时少展示，不强行凑数。
- 不把第二名冒充成某项纪录的第一名。
- 新增“隔一段时间后重新聊起”等选取类型只是候选；先定义规则、验证效果，再决定是否纳入。
- 去重后仍保留各项真实获选理由，不改变底层统计来制造多样性。

### 卡片内容

1. 日期、起止时间和必要的参与者信息。
2. 能辨认聊天内容的一段连续原文，保留发送者、消息顺序及必要的表情／表情包信息。
3. 消息数、时长与入选标签，作为次要解释。
4. 用户主动点击后展开更多上下文。

片段选择先尝试 6～10 条连续消息。不能机械取每轮前十条，也不能拼接远处的消息伪装成连续对话。可以围绕有信息量的发言选窗口；长轮次若取两段，明确标记中间省略。短句和表情可能是回忆重点，不能统一删除。算法只选择片段，不生成或改写聊天正文。

上下文来源和过滤范围必须明确；不可混回用户已排除的消息，也不可把过滤后的非连续记录伪装成完整连续原文。

### 轮次章其他整理

- 总轮数、时长中位数、平均每轮消息组成紧凑摘要。
- 私聊保留双方发起和首句响应；群聊保留可靠的发起者与本人数据。
- 开聊高峰可移至时间节奏区，与消息高峰使用不同名称和单位。
- 可增加轮次统计列表、时长分布或有效响应样本数；均为后续增强候选，不是本阶段必须一起完成的范围。
- 首句响应是发起者首次有效消息到另一方首次出现的间隔中位数，不扩大为全部回复速度。

### 完成判断

- [ ] 同一轮获得多个标签时只出现一次。
- [ ] 用户能通过原文辨认当时聊了什么，而非只看到数字。
- [ ] 原文未被改写，省略与未知时间有清楚表达。
- [ ] 展开／收起后阅读位置稳定；不自动展示整轮长记录。

## 5. 目标 C：关键词原文查看，默认安静

### 默认阅读与主动探索

- 鼠标经过关键词不弹对话、不自动展开、不造成布局跳动。
- 当前初版直接点词打开只读原话面板，不添加常驻下划线或数量角标。
- 面板独立滚动，关闭后恢复原词焦点与页面阅读位置；原纵向模块不因展开改变布局。
- 默认按导入顺序显示 3 条，提供“查看全部原话”；本轮不做随机“换几句”。
- 全部匹配列表暂按约 10 条分批渲染，支持继续查看；上下文由再次点击展开。
- 切换词只替换当前展开区域，收起后保留原阅读位置。
- 上下文按需展开，前后各最多两条、距命中不超过十分钟；不越过滤缺口或未知／逆序时间，不保证每个词都有精彩样本。
- 用户文本以只读方式显示，允许选择、复制；链接／富文本不能变成执行用户内容的入口。

### 匹配口径

| 入口 | 原文范围 |
| --- | --- |
| 语言画像常用词／特色词 | 当前成员、当前时间范围、当前过滤结果中，按同一词法规则匹配的消息。 |
| 表达文化中的伴随词 | 当前作用域内，同一消息同时含对应表达与该词；不能只搜索词。 |

必须分别记录“出现次数”和“包含该词的消息数”。一条消息中出现两次同一个词，计两次出现、一个原文条目。默认以消息为单位，不先按标点拆“句子”。

例如“出现 30 次，分布于 24 条消息”不能缩写成“24 次”。用户选择查看全部时，应可读到这 24 条匹配；统计与列表差异必须有明确原因，不能暗中截断。

前端不以字符串包含关系重建词频。匹配复用分析时的分词、清理、来源及成员规则；展示原文保持原貌。高亮需映射到真实文本位置，无法可靠定位时保留正文与匹配说明，不伪造命中范围。

### 共用的原文关联

- 先确定展示关键词与高光，再在应用／核心现有职责内准备其原文与必要上下文；不默认索引整个词库。
- 同一消息只在报告原文表保存一次，关键词和高光通过报告内引用关联。
- 报告内引用不能假定来源 message_id 永远唯一；重复／缺失 ID 不授权合并消息，可生成仅供该报告使用的引用。
- 复用原文显示、时间格式、展开与上下文组件；高光的精选窗口和关键词的完整匹配分别定义，不强行共用选择规则。
- 随新报告保存所需文本与关联，离线回看不重新连接来源、不重新分析数据库。
- 仅保存展示与回看所需材料，不为本功能默认导出全部聊天正文；原文是保留的用户撰写内容，不声称能从 ChatMessage 投影重建完整来源富媒体记录。
- 分页只减少 DOM 工作量，不能缩小文件；通过共用表、仅索引展示词及实际体积测试控制开销。
- 高频词达到数千条时，保存方式与体积阈值须实测决定。若能力受限，明确显示实际收录数／总数，不能宣称“全部”却只保存样本。

### 完成判断

- [x] 源码初版默认安静；自己／其他成员、时间范围与过滤按实际 token 关联。
- [x] 同消息重复词、多关键词、重复来源 ID 的计数与去重有定向覆盖。
- [x] 完整匹配列表分批显示，预览／全部有区别，离线浏览器验证通过。
- [ ] 表达文化伴随词的原文入口本轮未授权，保持原状。
- [ ] 真实报告阅读效果、超大群与旧机器响应待人工验收；虚构体积测量见实施审查。

## 6. 目标 D：让语言画像紧凑、具体

- 每个成员尝试组合“常说什么＋怎么说＋当时怎么说”，而非单独几个词占据整页。
- 常用词／特色词保持克制，沿用必要样本门槛；不为填空无条件增加词数。
- 私聊表达习惯可收成一行：文字长度与连发等；已有平均、中位、最长等数据按价值取舍，不重复铺大卡。
- “同频／谁更常这样说”可以切换，是否采用需验证，保留各自不同的统计含义。
- 群聊区分“自己常用”与“相对他人更具特色”；可以补次数、频率或比较依据，核心已存在的字段仍需接入展示模型。
- 群聊保留成员检索／滚动阅读的可扩展性，打印应避免只留下滚动窗口的可见部分。
- 样本少时卡片和章节自然缩短，样本不足时直接说明。
- 表情与表情包保留独立展示价值，不为填满关键词页重复搬运整套排行榜。

## 7. 目标 E：日期趋势与日／周／月均

这部分需要新增日期聚合，不能仅靠前端修改；可作为上述交互之后独立交付的小阶段。

- 保留并明确标注现有“活跃日日均”。若增加自然日日均，两者名称、分子与分母必须不同且可解释，不能静默更改旧值。
- 一张趋势图切换日／周／月粒度；均值随对应粒度出现，避免重复数字卡。
- 月均至少覆盖三个完整自然月才显示“完整月月均”。分子只取这些月内、能定位日期的消息，分母为完整月数。
- 已确认覆盖但没有消息的完整月计入零值；首尾不完整月可显示在图中并标记，不混入完整月均。
- 明确“分析选择区间”“首末消息区间”和“来源记录完整性”；消息跨过一个月不证明该月记录完整。
- 周均需先明确自然周起止、首尾不完整周及零消息周处理，不直接用日均乘 7 或总量除以有消息的周数。
- 星期比较可追加“每个周一平均多少条”或工作日／周末日均，但需按实际区间出现的天数归一化，不能用五天总量与两天总量推断偏好。
- 历史变化只描述消息量事实，不自动解释成关系升温、疏远或亲密程度。
- 日期热力图、7×24 时间热力图是候选视图；后者须逐消息真实交叉统计，不能将星期与小时两组边际分布相乘冒充观测值。

完成判断：完整／不完整月、跨年、零消息月、未知时间和短范围均有明确结果；均值与图表一致，不因样本不足展示误导性结论。

## 8. 文案与表达文化边界

### 文案方向

音乐气质主要由整体视觉和适量标题承担。指标标签直接、自然，避免每个模块都要求读者理解比喻。以下为待打磨示例：

| 当前说法 | 可尝试的方向 |
| --- | --- |
| 谁来起拍 | 谁先开口 |
| 接住第一句话 | 第一句之后，多久等到回应 |
| 一段乐句 | 每次会聊多久 |
| 接得最紧 | 消息最密集 |
| 几段特别的聊天 | 聊过的那些时刻 |
| 休止 | 简短统计说明 |

“最有来有回”目前主要依据发送者切换比例，不能据此认定语义上互相回应。标签或解释应说明“双方交替发言较多”。规则型聊天特征只作简短说明，不单独撑一页，不制造关系或人格判断。

### 表达与表情包

当前表达榜单排除 sticker，但旧表达聚合仍可能包含 sticker；“常用表达”数字显示的是裁剪后榜单长度。两章数量不可直接相加。表情包算法完成后重新核对实际边界，再决定文案和计数展示，避免本计划冻结即将变化的旧行为。任何统计口径变更需同步模型、消费者、语义修订和定向验证。

## 9. 必须维持的实现合同

- 分析核心计算统计，Presentation 选择、格式化与展示；不在页面复制另一套统计。
- 活动、轮次、成员、词法和表达继续使用同一过滤后的分析输入；查看原文不绕过过滤或扩大时间／成员范围。
- 未知时间消息当前计入总量及活跃日日均分子，但不计入小时／星期桶。任何新比例写明分母；旧行为变化单独说明与验证。
- 小时／日期统计使用统一聊天时区；原文时间与高光时间避免随浏览设备时区产生矛盾。
- 轮次间隔默认严格大于 1800 秒才分轮，等于 1800 秒仍同轮；未知时间与身份不猜测归属。
- 私聊／群聊保留不同分支，未知本人不当成对方；不能为了两列对称而补造数据。
- 展示榜单为裁剪结果，不能对其求和重算全局总量；样本门槛、不可用状态与图片 fallback 保留。
- 新报告可增加原文与图表字段；历史报告继续作为不可变快照重开，不能从旧统计补造原文或自动覆盖旧包。
- 保持离线 JSON／HTML 报告链；较大表情包报告可能带相对 media 文件，不能假定所有报告永远只有单个 HTML。
- 原文带来更丰富的本地报告内容；仅发布虚构样本和产品文档，不把真实聊天作为开发／调研资产上传。
- 合并章节需同步目录、锚点、编号、固定顺序测试、空态、响应式和打印规则，避免更新测试时丢失真实行为保护。

相关合同：[DATA_SEMANTICS](../DATA_SEMANTICS.md)、[ARCHITECTURE](../ARCHITECTURE.md)、[AGENTS](../AGENTS.md)。当前页面顺序守护见 [test_echo_group_sessions_frontend.py](../tests/test_echo_group_sessions_frontend.py)；前端行为见 [test_echo_conversation_sessions_frontend.py](../tests/test_echo_conversation_sessions_frontend.py)。

## 10. 建议实施顺序与验收

表情包算法完成是所有阶段的共同前提。顺序可以根据完成后的真实状态调整，不把全部内容捆绑为一次重构。

| 小阶段 | 可独立审阅的成果 | 暂不要求同时交付 |
| --- | --- | --- |
| 1. 第一章整理 | 摘要／节奏合并，小时精确读数和表盘原型，成员对照；紧凑及打印布局 | 完整日期趋势、所有候选热力图 |
| 2. 原文回忆卡 | 高光去重、真实片段、展开上下文；共用的报告内原文关联 | 全文搜索、来源聊天浏览器 |
| 3. 关键词小扩展 | 安静入口、精选预览、全部匹配、成员画像紧凑组织 | 全词库索引、复杂语义搜索 |
| 4. 日期统计 | 日／周／月趋势与定义明确的均值；同步文案和说明 | 新关系分析、全面数字书重构 |

上表保留最初分阶段设想；当前先完成关键词初版，第二章原文卡延至 0.4.0。
可复用报告内原文引用，但无需先搭建通用平台。

验证使用虚构数据，按变化选择 focused 与受影响的 UI／Report Domain；无需为规划文档运行程序测试。实施时重点验证：

- 同一轮横扫多个高光、不同轮获选及只有一轮的情况。
- 多次词命中与消息数不同、同名成员、未知身份、重复／缺失消息 ID。
- 过滤范围、伴随词同消息约束、保留文本与高亮的一致性。
- 小样本、全无有效时间、完整月和不完整月。
- 私聊、小群、超大群；长文本、多关键词、长列表及报告文件大小。
- 鼠标经过无弹层，明确点击才展开，键盘可用，收起位置稳定。
- 离线重开、既有媒体 fallback、移动端与打印的完整可读性。

没有原型／人工阅读验证前，不把“可运行”写成“回忆体验已完成”。

## 11. 本轮不包含

- 未经确认实施其余候选，或扩展表情包算法与布局。
- 群聊互动关系、引用回复网络、合并转发等新专题。
- AI 摘要、语义推断或自动关系评价。
- 全面重写电子书、海报、分享与导出系统。
- 新数据源、来源获取／解密改造及无关安全审计。
- 为上述小目标预建大型检索服务、插件框架或独立消息浏览平台。
- 批量改写历史报告、绑定未经确认的版本号／发布日期。
