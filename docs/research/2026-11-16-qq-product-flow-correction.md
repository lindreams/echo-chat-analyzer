# 独立 QQ 产品流程纠偏与获取前置缺口

本轮只读检查源码并使用虚构数据，不访问真实账号、配置、数据库、聊天或 QQ 进程，
不取钥、不登录、不构建候选。保留此前已验证的认证解密、名称、媒体、分析与报告组件。

## 目标与实际实现的差异

目标是正常客户端登录后自动发现当前账号的群聊和私聊，再在既有列表中选择会话与时间。
上一轮显式填写账号、账号目录与群号，只能物化一个群 payload，不能代替这个目标。

当前 `QQDatabaseProvider.list_sessions(self_uin=...)` 已枚举 `group_msg_table` 和
`c2c_msg_table`，会话使用带类型的分区键；`find_session` 与读取按类型选择表，再按
分区键限定。缺口不在列表控件，也不在分析或解密算法，而在其前面的独立获取阶段。

### 可信当前账号与数据库目录尚未自动产生

- `application/qq/qq_independent_service.py::QQIndependentSelection` 的账号、目录及群
  全部来自调用者；`prepare` 只检查输入形态及目录名匹配。`_select_process` 验证 QQ
  镜像、PID 和创建时间，没有读取或证明登录账号，也不返回数据库目录。
- `providers/qq_independent/js/qq_login_event_probe.mjs::observeCdeResponse` 仅解析目标
  响应中的取钥材料；`session.mjs` 在捕获前就接收已选定快照和首页。结果没有当前 UIN、
  UID 或账号目录绑定，不能从取钥成功推导出一项尚未提供的账号身份声明。
- 旧 `scripts/qq_direct_db_snapshot/snapshot.mjs` 在获取前后检查
  `core.selfInfo.online/uin`，并从 `core.apis.DatabaseApi` 获取数据库能力；Python 的
  `_validated_generation` 再校验 manifest 中的 `qq_uin`。这些上游证据来自旧进程内
  桥接上下文，独立 worker 没有等价来源。重新引入该桥接不符合本轮边界。

不能以唯一数字文件夹、最后使用账号、分区名、昵称或消息内容代替当前登录账号证据，
也不能为寻找匹配库扫描或读取其他账号数据库。

### 登录页状态与现有快照前提不相容

`providers/qq_independent/snapshot.py::prepare` 在复制前后均要求 QQ 完全退出，
禁止 WAL/SHM，使用禁止写入的源句柄并复核身份、大小与摘要。当前产品要求点击
「我已准备好」时 QQ 已打开且停在登录页；直接沿用此入口必然拒绝。
不能删除退出检查、忽略辅助文件或把一次普通文件复制当作一致快照。
旧 main/WAL 合并组件仍保留，但旧获取编排依赖数据库 API 和在线身份上下文，
不能仅将其接上就宣称独立账号绑定、快照与捕获时序已经成立。

## 本轮改动与保留

- 撤下手填表单、准备／等待登录动作及其 Facade 准备方法。正式 QQ 页面明确连接不可用，
  保留现有会话面板但禁止交互，不发出 armed 或登录提示，也不启动新获取。
- 即使其他实验调用者已准备单群，导航仍不能将它作为自动会话发现成功展示。
- 显式受限单群的服务和既有身份、清理、报告回归保留；窗口关闭仍通过 Facade 取消、
  排空已有获取。没有重写取钥、解密、名称、媒体或微信逻辑。
- 不保留第二个正式 QQ 工作流，不恢复 NapCat 或额外二维码。

## 下一步所需最小证据与停止条件

须先取得独立来源的同一 QQ 进程代际 → 当前已登录账号 → 数据库目录可靠绑定，
以及该流程中可建立一致加密快照的时点与证据。后续受限验证应只核对身份／路径的
绑定结果、登录页的数据库持有及辅助文件状态；公开回执仅记录计数和校验结果，
不输出身份、路径、密钥、昵称或正文。任何未知、冲突、提前登录、超时及释放未确认
均停止，不通过实验表单或猜测继续，也不自动重试。

本轮没有新的真实实验授权，因此停在这个获取前置缺口；不是只剩一次 GUI 真人验收。
补齐后才能复用现有 Provider 枚举、逐会话严格校验、名称与媒体上下文，验证虚构多群／
私聊选择和时间隔离的完整 GUI，再构建 Frozen/Setup 候选。
