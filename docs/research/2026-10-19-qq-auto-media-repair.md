# QQ 自动媒体获取：修复与真实复验边界

本轮仅处理自动媒体调度、脱敏诊断和必要的低样本展示；不改变统计、排名、
招牌资格、数据源或认证合同。保留已有研究记录，不以本记录替代真实 QQ 验收。

## 已确认与未确认

正式入口为 MainWindow → QQWorkspace → SessionAnalysisPanel → workers.submit →
Facade.analyze_session → 同一份 Direct DB payload → 自动媒体 → 解码 → 报告装配。
线程回调由现有 QObject relay 返回 GUI；没有新增任务框架或 processEvents 补丁。
媒体 I/O 期间不持有 Facade 的 shutdown/publication 锁；分析服务 lifecycle 锁仅用于准入计数，
不包住下载和装配。源码检查及虚构场景没有发现这条链上的主线程同步等待。

**真实 GUI 卡死尚未复现，根因未确认，不能宣布 P0 已修复或真实验收通过。**
虚构慢请求、超时、失败、取消均经私聊和群聊正式生成按钮运行；下载、解码、装配的线程归属
与 Qt 事件循环响应有定向检查。新增 GUI 心跳只观察事件循环间隔；超过 1 秒记录
analysis-gui-stall，结束时记录最大间隔。完全卡住时它要等事件循环恢复才有日志，
不能据此排除原生代码长时间占用 GIL、锁等待或特定运行环境故障。

已确认两个调度缺陷：

1. 原 60 秒批次每次开始前要求剩余至少 35 秒。已有虚构复现：第一项耗时 26 秒后，
   后续全部没有请求机会，34 秒剩余预算直接闲置。现改为使用实际剩余时间，
   仍受查询 8 秒、客户端传输 25 秒、解码协作式 2 秒和原有安全限制约束。
2. 原目标顺序先处理成员个人 Top 10，再处理全群榜；成员长尾可用尽 32 项额度，
   全群榜完全没被请求。现先全群／共同榜，再招牌，再按名次轮转个人榜；目标集合及排名不变。

另修正了被跳过的每个目标仍排队发出 GUI 进度更新的问题：仅对实际尝试刷新逐项进度，
跳过原因留在脱敏诊断；定向复现从 10 个目标/3 次请求的 10 次更新降至 3 次。
这减少大群的无效回调，不代表已证明它就是真实卡死的根因。

这两点能够解释“报告需要图片但根本没发起获取”的部分情况，不能证明真实五素材中
某张为何失败，也不能证明所有大群无图都来自预算。

## 脱敏诊断与失败分类

日志只新增随机 batch、目标序号、固定阶段/错误码、耗时、线程标志及计数，
不记录消息、会话/账号身份、素材摘要、路径或媒体内容。只分享这些新增诊断行，
不要分享完整日志、报告 JSON/HTML 或真实媒体。

同一个 batch 的 target 按本次导出的 assets 顺序编号，从 1 开始；它不是消息 ID。
先看 sticker-media-plan，再看 stage/result，最后看 asset/export。GUI 心跳按同一轮
生成的时间段对应。stage 中 elapsed_ms 属于前一阶段，next 表示即将进入的阶段；
result 的 elapsed_ms 是该目标的总耗时。

| 类别 | 证据 |
| --- | --- |
| 未进入请求 | plan 为 local/unsupported，或 result 的 stage=not_requested；不能计作 QQ 下载失败 |
| 消息无法定位 | stored_message_missing/ambiguous，或 kernel_message_missing/ambiguous；对应固定 Facade 错误码 |
| PIC 元素无法定位 | stored_element 或 kernel_element_unconfirmed 阶段失败 |
| 身份复核失败 | stored_identity/kernel_identity，qq_media_group_*_unconfirmed 或 qq_media_mapping_rejected；保留消息、会话、时间、成员、元素、UUID 和摘要校验 |
| QQ 内核查询/获取失败 | qq_media_query_failed、qq_media_query_timeout、qq_media_message_query_failed、qq_media_api_unavailable、qq_media_download_failed；固定码不推断资源过期 |
| 下载超时 | qq_media_download_timeout 表示桥接报告原生下载超时；qq_media_transport_timeout 表示客户端未及时收到完整响应，两者不同 |
| 传输/解码限制 | qq_media_too_large/transport_limit/transport_invalid、qq_media_decode_budget/invalid_content；失败字节不进入报告 |
| 批次预算 | report_media_time_budget、report_media_request_budget；前者未获机会不等于已下载失败 |
| 在途状态未知 | report_media_inflight_unknown：客户端传输超时或 busy 后，不能证明远端下载结束，停止后续获取，不绕过单媒体在途限制 |
| 报告装配 | asset 的 embedded、report_asset_budget、report_image_unavailable、upstream_unavailable；export 失败为 report_assembly_failed |

sticker-media-batch 记录目标、可原生获取目标、尝试与实际可用数量；calls 记录 Provider
查询/下载方法调用数，它不证明桥接/内核已接受请求。stage=kernel_query 表示进入 Provider
调用；收到定位结果才能证明查询返回。无法确认传输是否到达 QQ 的场景保持未知。
取消时 sticker-media-stop 记录当时尝试、调用、完成数量，不继续发布报告。

## 当前预算的实际影响

- 素材阶段保持 60 秒、最多 32 个缺图 PIC 候选，串行且不重试；本地搜索和身份准备也消耗时间。
  请求耗尽时间仍会使剩余目标没机会；本轮去掉了额外闲置的 35 秒启动门槛，没有承诺全部恢复。
- 32 项只覆盖本报告选中的目标，不是 4,916 种素材全量获取；目标过多仍有未请求项。
  桥接还保留各 64 次/滚动 60 秒的查询与下载额度，多轮报告生成会共享它，等待后恢复。
- 单次传输 2 MiB、单帧 4M 像素、单素材累计 32M 像素及逐帧工作量限制保持；
  本地扫描预算及报告内嵌原始图片 16 MiB 总预算保持。取回并验证不等于一定能装进报告。
- socket 超时、原生解码与文件操作不是可强制打断的进程级硬截止。取消先恢复 GUI，
  停止新工作并抑制迟到结果；已有请求返回前仍占本轮资源，不能把“页面返回”当作 QQ 已停止下载。
- 普通报告只显示图片可用性提示；没有发送与有发送无图分开。≤5 次发送提示样本较少，
  保留统计和原排名，不描述为代表性个人习惯。详细技术原因留在本机诊断。

## 同一张真实 PIC 的对照实验

1. 选测试群/测试私聊中可明确指出的一条 PIC 发送，记为 A；全过程保持同一会话、
   同一发送记录，不转发或重发来替换样本。不用 MFACE 作为 PIC 下载对照。
2. 先做一次自动生成，保存原报告并仅在本机记录 A 的图片是否显示、原件/可信预览、
   墙钟时间、batch/target 及固定失败码；记录请求是否真正进入查询/下载。
3. 用 QQ 客户端打开同一条 A，确认是否显示完整图片／动画，记录首次打开的等待。
   再正式生成同一范围报告，检查是否仅客户端打开后才恢复。
   客户端和媒体下载可能更新缓存，须记录执行顺序，不删除聊天记录或缓存来重置。
4. 在另一条测试发送上改变顺序（客户端优先），帮助识别缓存影响。
   只在本机比较状态、耗时与原件／预览，不上传记录、图片、身份、路径或报告。

独立素材窗口与单项手动获取已退休。自动获取已验证但报告无图时检查装配；
身份或下载失败保留固定分类，不能直接归因于缓存清理、网络或资源过期。

## 验证及留项

本轮使用项目显式虚拟环境，核对了目标源码导入及依赖；测试使用隔离目录和虚构数据库/媒体。
十模块定向回归首次为 410 通过、2 跳过、4 个旧展示文案断言失败；更新展示断言后，
受影响七模块复跑 191 通过，正式 QQ/媒体模块复跑 42 通过，身份/代际保护另测 33 通过。
原件/预览状态、图片字节与统计断言保留。两个跳过项因 Windows 缺少符号链接权限，
没有放松相应生产校验。`git diff --check` 通过。
未启动真实 QQ、未读取真实账号数据；未运行 Full、
Frozen/Setup 或跨机器验收，不覆盖这些发行结论。

真实复验仍须检查：原卡死能否重现及心跳间隔；原五素材逐项分类；原大群总榜实际图片数；
慢请求取消后不发布迟到报告、在途请求最终释放；客户端与正式报告对照；取消后重试的
滚动额度与在途状态；保存后的自包含 HTML 是否离线显示完整图片/动画。

成果保留在当前任务分支工作区，未经提交、推送或合并，等待真实 QQ 复验；
现有研究文档和其他未提交成果继续保留。真实 GUI 卡死根因的确认是本轮尚未完成的 P0 留项。
