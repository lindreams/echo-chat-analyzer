# QQ 最后一次有界身份核查与待决策的降级产品

基线：`spike/qq-independent-source`，`f6af7af`。只核查独立消息方向与既有取钥请求／响应关联，
不重复已排除的作者、名称、外部 self 反向认证，不继续寻找登录回调。
本轮只读仓库源码和固定提交的公开字段资料，运行既有虚构定向测试；
没有访问真实 QQ、账号资料、聊天库或安装模块，没有新增 Hook、取数或构建。

## 明确的技术结论

**在本轮允许的现有证据范围内，两条身份链均未达到生产准入条件。结束身份逆向研究。**
这不表示没有可分析的数据，也不表示发现的候选字段绝对无效。
下一步可由负责人批准改为“明确授权所选本地资料、凭据认证快照、本人身份未知”的导入产品。
该方案不再承诺认证本地资料属于当前登录本人；这是需要明确批准的产品与准入合同变化，
不是对当前账号校验的静默放宽。本轮没有实施该变化。

### 一、确实存在方向字段候选，但独立本人语义尚未证实

既有 Provider 的消息查询未读取 `40013`；Adapter 和媒体事实也未消费独立来源方向标记。
外层 `40011/40012` 用于消息类型，PIC 的段子类型用于素材判定，均没有提供已验证的本人角色。
现有报告核验中的 `direction_verified` 是相对于外部本人上下文的核对，不能升级为独立方向证据。

固定参考提交 `317024ce2c5e3482fdf9f310a5a7159ab4927e34` 提供了新的具体候选：

- [群聊 `40013` 原始字段研究](https://github.com/QQBackup/nt_msg_db_util/blob/317024ce2c5e3482fdf9f310a5a7159ab4927e34/db_docs/group_msg_table/40013.md)
  将它描述为多值发送／来源标志，含普通发送、接收及系统／特殊情况，要求结合其他字段使用。
- [私聊 `40013` 原始字段研究](https://github.com/QQBackup/nt_msg_db_util/blob/317024ce2c5e3482fdf9f310a5a7159ab4927e34/db_docs/c2c_msg_table/40013.md)
  同样给出方向解释，并记录特殊值及历史迁移异常。
- [同一提交的研究边界](https://github.com/QQBackup/nt_msg_db_util/blob/317024ce2c5e3482fdf9f310a5a7159ab4927e34/README.md)
  说明结论来自其研究快照，换版本或数据库须重新验证。

这是有价值的字段线索，不是本轮可采用的可信本人证明：现有 Echo 受控记录没有覆盖目标
54395 的该字段语义，也没有证明其本人标签来自独立确认，而非先挑出本人候选再对照发送者。
公开文档中的相符关系和置信度标签不能单独排除这种循环。虚构一个 `40013=1` 行再写验证器，
只能验证人为设定的规则，不能验证 QQ 的角色含义；本轮不这样制造通过证据。

若该语义可靠，本来可以从独立的本人发送标记与同一行作者建立候选，并要求所有可信本人行
只对应一个规范账号；零本人行、冲突作者、未知格式都应拒绝。但目前没有满足前提的独立证据，
故未实现该推断，也不为此继续采集、扩大逆向或安排登录实验。

### 二、既有事件上下文能证明传输来源，不能配对账号请求与凭据响应

| 已有证据 | 能证明 | 不能证明 |
| --- | --- | --- |
| `identity_metadata.inc` 的固定 36 字节记录 | 目标发送任务上的账号字符串候选和原始类型 | 没有请求序号、响应关联键或已定义的通用本人角色 |
| `adapter.cpp::inspect_response` | 固定目标命令的成功响应载荷 | 没有同时导出的账号或可与发送记录匹配的请求标识 |
| `session.h/cpp` 的进程创建时间、私有管道 nonce、单次会话 | 本次 Echo 传输绑定到指定进程代际，防止错进程／错管道交付 | nonce 是 Echo 创建的，不是 QQ 请求标识；同进程可含多个账号上下文或同命令任务 |
| `connect.mjs` 的 `sessionGeneration`、首个事件与页摘要 | Echo 任务范围、事件数量及待认证输入绑定 | 不会产生 QQ 请求与响应之间的账号关联 |
| 日志格式中的 `seq` | 固定函数含该日志锚点 | 不能证明当前已读取、传递或核验了对应序号 |

发送元数据与响应捕获还是不同编译配置，当前记录无法做严格 join。
只匹配命令、同一 PID、时间邻近或两个观察都为首条，均不能排除多账号误配。
单次传输只交付一个事件也不表示 QQ 只发过一个请求。不能用 Echo 的任务编号替代 QQ 请求编号。
因此本轮不新增配对器、不猜测字段偏移、不新增 Hook；这条链也未成立。

相关实现：`scripts/spikes/qq_native_event/{identity_metadata.inc,adapter.cpp,adapter.h,session.h,session.cpp}`、
`src/qq_chat_analyzer/providers/qq_independent/js/{connect.mjs,qq_login_event_probe.mjs,qq_key_source.mjs}`。

## 推荐负责人决策的第一版产品

名称：**QQ 本地资料分析（本人未验证）**。推荐采用这一版以恢复可用 GUI，
同时结束把持续在线登录身份作为该版本前置的路线。以下均是待批准方案，尚未改变现有行为。

1. GUI 只在已知的本地资料位置发现候选，先展示资料条目，不读取未选条目的聊天内容。
   账号目录标签只标“本地资料标签，归属未验证”；不展示为已登录／已认证账号。
   用户从列表主动选择并明确授权一个资料集合，无手填账号、群号或数据库路径入口。
2. 分步引导用户自行打开正常 QQ，使用既有受准入组件的单次获取能力；真正 armed 后才提示正常登录。
   只收取本次一个有界凭据事件，不缓存旧凭据、不遍历其他账号尝试认证、不自动重试或结束 QQ。
   在等待用户完全退出期间，只持有有界原始凭据事件；不把认证 raw key 租约带出同步消费域。
   取消、到期和异常都结束本次任务并清理自有资源，不允许无限延长等待。
3. 用户完全退出 QQ 后，按既有源锁、对象身份、摘要和 sidecar 条件固定所选数据库快照。
   当前冻结入口若仍发现 WAL／SHM 就拒绝，不能删除它们或退化为普通复制。
   后续若使用其他既有一致性路径，须维持相应完整校验与授权，不能因本人未知放宽。
4. 本次凭据必须认证所选固定快照的全部页，解密后 SQLite 完整性通过，才允许会话发现。
   错钥、认证失败、输入改变和资源状态未知均拒绝。不尝试其他未授权资料来寻找能解密的库。
   此时证明的是凭据与这份数据相符；不声明账号本人身份或跨库同一账号身份已经认证。
5. Provider／Adapter 的 `self`、每条 `is_self` 和报告 viewer 均保持未知；目录标签和选择动作
   不写入本人上下文。按现有列表选择群聊／私聊，再选时间范围，经 Facade 复用统一分析和报告链。
   私聊条目标为“私聊记录”，可展示有来源的会话对象／作者名称，不能自动称为“你的好友”。
6. profile／group 名称库只有在本次资料授权范围内、各自快照认证通过且关联无冲突时才作名称补充。
   同一凭据能解密多库不证明它们属于同一账号；不自动扩读其他账号缓存或元数据库。
   无可靠对应关系时使用作者标识／未命名标签，不从名称推导本人。
7. 所有报告和导出都携带“本人未验证”状态，缺失值不写成 0 或 `false`。
   临时明文、凭据和自有进程仍遵循现有所有权与失败清理合同；只有用户生成的正式报告持久保存。

界面确认文案建议：

> 仅在本机分析你选择并授权的 QQ 资料。Echo 会校验凭据与数据快照是否匹配，
> 但无法确认资料归属或哪位发言者是你。“我／对方”及相关互动分析将不可用。

### 功能边界与现有实现差距

| 功能 | 本人未知时的产品处理 | 现有证据／需要的最小调整 |
| --- | --- | --- |
| 群聊／私聊分区、消息列表、时间范围 | 可保留；按所选快照与分区限定，名称歧义不影响选择范围 | Provider 可不传 `self_uin`；私聊 `peer_uin` 不应按未知本人排除推导，会话对象不当作已验证好友 |
| 消息总量、日期／时段、词频、原话、每个可靠作者的语言画像与活跃度 | 可保留；按作者名称／稳定标识描述，不使用“你” | 统一分析按作者工作；未知作者仍单列，不合并成某个已知成员 |
| 群聊按成员的排行、开场者、群聊特色词 | 可保留中性成员统计；不突出本人 | 群聊成员／发起者统计不要求 self；本人开场量与本人占比必须隐藏 |
| 私聊轮次数、时长、全部消息量 | 可保留总览与时间事实 | Core 已保留三态；“我／TA”轮内计数、谁更主动、方向回复等待与开口时段必须禁用 |
| 私聊分别按作者的常用词 | 可按名称保留；不标“你／TA” | 现有语言标题在 viewer 缺失时可用名称；私聊共享词的展示目前要求 viewer，第一版保持禁用，不为它新增双人角色推断 |
| 表情／表情包总量、群聊按作者统计 | 可保留不依赖本人的总量／成员事实；素材不足时显示缺失 | 私聊“我／TA”使用量、专属／共享对比、采用／接力等方向故事第一版禁用；不能把未归属计数归给任何一方 |
| 拍一拍／戳一戳、本人徽标、本人专属筛选 | 必须禁用 | 动作角色映射需要可靠本人；也不提供“选一个人就是我”来制造可信 self |
| 素材恢复 | 第一版关闭自动账号缓存发现与原生下载，可保留无图统计 | 如以后允许本地素材，仅能在另有明确授权的窄根内按消息摘要验证；不从资料标签扩大缓存权限，不恢复旧桥接路径 |
| 导出报告、历史报告查看 | 可保留中性报告；未知状态在 JSON／HTML／GUI 中一致 | 不能只改 GUI 提示，留下导出中的错误本人标签或零值 |

这不是“清空 self 即可直接上线”：私聊开场 Core 仍会产生已识别 self／peer 的计数 0，
HTML 的开场图含固定“你／TA”标签；私聊表情章节也保留“我／TA”空位。
若批准降级，必须在 Facade 的来源结果、报告数据及展示中贯彻未知状态，隐藏这些比较和标签，
不能把统计上的“未确认”表述为“本人发送 0 条”。
本轮仅记录这些接线要求，没有修改分析或报告行为。

## 本轮验证与成果去向

使用当前工作区显式 `.venv`，核对实际源码导入、Python、目标 runtime／dev 依赖和 pip 一致性。
测试启动前隔离用户目录及临时目录，只运行既有的五项虚构定向测试，全部通过：

- Adapter 本人上下文不可靠、命名空间错误时保持未知；
- 群聊本人发起统计要求可靠身份；
- 私聊轮内双方数量在未知身份出现时保持缺失；
- 表情包本人未知时不根据参与者推断。

没有新增测试框架、重复离线取钥实验、运行真实数据或执行完整 GUI／Frozen／Setup 验收。
公开资料只读，未下载或运行参考工具，也未复制其实现。
本轮仅新增本研究记录；此前提交和未知未跟踪目录保持原样。
隔离测试输出留在忽略的 `build` 范围供本项审核复核，审核结束后按所有权规则处置。
未改 main、合并、推送或发布。

**待负责人最终决定：是否批准上述“明确授权本地资料、本人未知、保留中性分析”的第一版。**
批准后才修改来源准入及正式 Facade／GUI，以虚构多账号、多会话完成验收，再统一申请真实全流程验收。
