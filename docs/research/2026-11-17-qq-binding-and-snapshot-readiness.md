# QQ 当前身份与活动快照：生产准备收敛

接续 `da9865e`。本轮只读源码、修改共享获取组件并使用虚构数据验证；没有查询 QQ
进程、Hook、取钥、解密真实数据库、读取聊天或进行新的实机实验。设备句柄分类器不变。
此前真实路径／锁证据见 [元数据验证记录](2026-11-17-qq-identity-metadata-probe.md)。

## 当前身份绑定契约与唯一缺失证据

以下是后续正式获取必须满足的契约，不是声称已有身份生产者。独立服务当前仍不能
自动发出一份满足全部条件的绑定；不增加可通过调用者填布尔值伪造的身份对象。

| 绑定项 | 必须成立的来源与验证 | 当前状态 |
| --- | --- | --- |
| QQ 进程代际 | 已验证的 PID、创建时间、镜像及固定版本／wrapper 摘要；保留进程句柄复核 | 现有生产组件具备 |
| 本人身份 | 明确本人角色的当前登录态声明；规范 UIN，不能用数字外观猜账号类型 | 仅有受限发送任务候选与独立已知 UIN 匹配、原始类型 0 的证据 |
| 登录代际 | 与本人在线状态同源，在连接、断开、登出、重登、换号、事件源更换或失联时失效 | 独立组件尚无可信生产者 |
| 账号目录 | 同一进程代际持有的实际句柄路径，唯一账号目录、主库及辅助文件检查，与已确认本人 UIN 匹配 | 真实复核已通过；目录绑定谓词已进入生产模块 |
| 获取代次 | 单次准入及加密输入的任务标识，只用于隔离本次操作 | 现有作用域具备，不是 QQ 登录代际 |

**唯一缺失的身份来源是：同一已验证 QQ 进程中，能够证明当前在线本人 UIN，并能在
同进程登出／重登／换号时可靠失效的登录态生产者。** 路径关联已经取得证据，不再
要求通过重复目录或锁实验补足它。单次发送 task 的账号字段没有本人在线角色和连续
登录状态，不能把原始类型 0 升级为通用枚举定义或持续有效凭据。

现有 `connect.mjs` 的随机 `sessionGeneration` 是私有传输／密钥作用域标签；
`qq_key_source.mjs` 的数据库指纹证明输入页与密钥相符；事件源的 `isCurrent` 目前
只覆盖取消。三者均不能替代 QQ 登录代际。旧快照入口的 kernel login listener 和
`core.selfInfo` 说明旧链路如何失效，但这些值由旧桥接上下文提供；本轮不恢复该依赖。

正式实现获得上述生产者后，绑定必须按下列规则使用：

- 在路径获取、加密快照之前以及源锁释放后分别复核同一进程／登录代际和本人 UIN；
  发布会话列表或 payload 前再次确认。跨代响应、旧任务及旧凭据不得重放。
- 进程退出／重启、登录转换、换号、事件源更换／失联、身份冲突或路径不唯一，立即
  使绑定失效并取消当前获取；同 PID 不代表同进程代际，同进程也不代表同登录代际。
- 重新绑定只能来自新的可信登录声明，不能自动使用旧 UIN、目录、随机标签或 MAC
  成功恢复绑定。未知登录转换等同无效，不以短 TTL 或前后一次相同采样补作连续证据。
- 授权账号参考只证明本次读取范围。目录匹配通过不能产生“当前本人已确认”状态。
  不增加手填入口，不把虚构测试中的来源替身接入正式 GUI。

## 活动加密快照的生产收敛

复用现有 `scripts/qq_direct_db_snapshot/main_wal.mjs`、`source_guard.mjs` 与
`source_guard.ps1`，不改 SQLite 锁位、SHM 格式、密码算法或原关闭主库安全检查。
新增 `createLockedMergedEncryptedDatabase`，将原获取入口已有的三步编排收敛到
共享组件：取得源锁 → 固定提交边界并合并加密输入 → 确认源锁与 helper 释放。
原 `snapshot.mjs` 和独立认证交叉验证共用此入口，不复制合并器或建立新的下载／解析层。

该入口要求调用方提供有限的整体截止时间；锁、SHM 及复制共享同一剩余预算，不为
每阶段重启计时。锁仍有现有 65 秒上限。取消／到期在复制中及释放后检查，源锁释放
失败不得返回成功。输出路径和失败清理由已有 workspace owner 负责；包括释放失败
在内的任何异常都必须丢弃 staging，不能将加密输出交给认证／解密或发布。
原正式入口保留其 `discardStaging` 及清理失败封闭准入行为。

完整性保护保持原实现：

1. 在源锁下读取一致双 SHM 头及校验和，固定已提交边界 B、salt、页数及 backfill／attempted。
2. 校验至 B 的 WAL 帧、salt、checksum 和提交标记，以对应页覆盖主库；B 后提交不扩展输出。
3. 对主库各批次和整体内容、文件身份与大小、WAL 至 B 的完整前缀和前后 SHM 代际
   复核；替换、截断、checkpoint、回卷、损坏、未知见证、超时或取消均拒绝。
4. 只有源锁及 helper 释放确认后才返回加密快照。随后仍必须走既有逐页 MAC、同步
   密钥作用域与 SQLite 完整性检查；锁获取成功本身不能成为快照成功条件。

这仍是共享生产组件的准备，尚未接入独立捕获 worker 或 Frozen 资产清单。
当前独立 `connectOnce` 在启动前要求首页，并在停止观察后立即进入同步认证消费者；
不能在该回调中 `await` 活动复制，或把密钥带出作用域等待身份。身份来源成立后，
须在认证前安排有界加密快照并共享剩余预算，复核登录代际，再同步消费已冻结输入。
停止观察也不等于 DLL 已卸载；相关驻留与准入合同不变。

## 离线验证与实际边界

沿用已有 main／WAL 与独立认证用例。48／80 字节保留区的虚构数据库在边界 B 选定后，
由独立写入进程追加提交，另一个映射写者发布 SHM，不用随机等待或真实 QQ 数据。
捕获期间确实保留源锁，后验提交帧增多，但输出读取仍为 B 的旧值；逐页 MAC 全通过、
SQLite `integrity_check` 为 `ok`，认证消费者只在释放之后运行。源文件成功重命名验证
无阻止删除的源句柄遗留。原主库／WAL／SHM 破坏、输出冲突、取消、认证损坏与清理
失败回归保留，只增加整体预算在开始前过期的必要拒绝场景。

最终代码的两份相关回归 **86 passed**，包含上述独立写入、48／80 字节逐页认证、
SQLite 完整性、损坏拒绝、取消、预算过期、输出所有权和源释放场景。仅增加一个预算
过期参数场景，没有新增测试模块。使用已验证的显式解释器、当前工作树源码、Node 与
隔离用户目录；未安装或升级依赖。`git diff --check` 通过。

虚构测试的成功不证明真实 QQ 的完整快照，也不证明当前本人／登录代际的来源。
此前真实授权只检查路径与锁，没有复制真实 main／WAL。

## 停止条件与下一次最小验证

本轮在身份生产者缺失处停止，不连接 GUI、不构建候选，不再扩展诊断器。

下一次应只针对同一授权账号、固定 QQ 版本，验证一项当前登录态来源及其生命周期：
登录成功后确认本人角色和 UIN，与已验证进程／目录关联；同进程登出使原绑定失效，
同账号重登必须产生新代际，旧代际保持无效。无需读取其他账号、聊天、密钥或数据库页；
如果无法取得可靠的失效信号，就拒绝该来源，不以周期采样掩盖缺口。涉及进程内元数据
观察须另行明确授权，不能以本轮离线许可启动。

上述身份来源成立后，真实一致性快照另需明确授权：只对已绑定账号固定库获取受锁保护
的加密 main／WAL 副本，核对边界、变化拒绝、总预算和释放；不将路径／锁回执当作
已完成快照。只读校验应不解密、不读取聊天，产物限自有受保护临时目录并按方案清理。
三库各自的固定边界也不能被表述为跨库事务一致性。

此前 `.qpt-*` 及来源不明目录保持不动；本轮虚构资产位于忽略的 build 范围，待本项
准备工作审核与研究收尾后处置，不进入 Git。不修改 main，不合并、推送或发布。
