# 独立 QQ：账号证据与活动快照的离线核验

在研究分支、`f6bd904` 上接续。只读审核既有脱敏记录与源码，测试只使用虚构数据库，
没有读取真实账号、配置、聊天、缓存或进程，没有登录、取钥、Hook、构建候选或修改 GUI。
此前被审核拒绝清理的目录保持原位；本轮测试产物位于 Git 外的 build 目录。

## 结论

**账号自动绑定尚未解决。** 已验收的身份来自负责人明确提供的账号和群，以及受限目录。
真实事件与数据库 MAC 闭环证明密钥／数据库一致，不产生额外的“当前登录 UIN”声明。
现有独立原生协议没有传递这种声明，不能从已清理的原始事件中离线补出它。

**活动快照找到了可复用且已通过离线交叉验证的路径，但未取得独立 QQ 实机闭环。**
旧 main/WAL 合并器和源锁本身不依赖 NapCat；依赖旧桥接的是获取账号、数据库位置和
解密的上层编排。本轮证明可将其输出交给已验证的独立 SHA1 认证解密器，保留 48／80
字节兼容及所有源稳定性检查。未改变正式获取时序或取消“QQ 退出”检查。

完整 GUI 尚未贯通，不构建依赖这两个前置的产品流程，也不能直接安排最终 GUI 验收。

## 一、身份关联究竟证明了什么

| 关联 | 已有来源及校验 | 不足以证明的内容 |
| --- | --- | --- |
| 账号 → 账号目录 | 实验显式输入；`QQIndependentService.prepare` 比较目录名与输入账号 | 该账号是否本次 QQ 的当前登录者 |
| 观察 → QQ 进程 | 明确镜像、创建时间、wrapper 版本与摘要、唯一目标进程、私有传输 | PID 或同一模块不能声明账号 |
| 登录响应 → 数据库 | 同代目标事件，首页 MAC；随后逐页认证与 SQLite 校验 | 认证证明库／密钥一致，不返回 UIN 或数据库目录 |
| 群 → 消息分区 | 明确授权群号，`40030` 及同一行 `40021` 见证，严格逐行检查 | 群号、分区或发送者都不是当前登录账号 |
| UID ↔ UIN → 名称 | 已授权 profile／group 元数据的稳定关联、冲突拒绝 | 已读字段描述成员或联系人，没有验收过“本人”角色字段 |

`metadata.scoped_names` 的输入本来就含已授权群和报告成员 UIN；它恢复名称，并没有
发现当前账号。旧 `snapshot.mjs` 从 `core.selfInfo.online/uin` 和
`DatabaseApi.getNtDbDir()` 取得身份与位置，再检查代际；独立服务没有等价生产者。

重新核对固定修订的 [QScope profile](https://github.com/sj817/QScope/blob/0ee1533bb18c4ebdd918c355de27c204209acb3e/collectors/qqnt-windows/profile.json)：
作者将发送 task 的 UIN（`+0x38`）与类型（`+0x50`）明确标为静态假设，运行值尚未观察。
它不是现有接收对象的已验证字段；当前 `adapter.cpp::inspect_response` 在接收对象
`+56` 读取的是 payload vector。不能混用结构或把静态猜测升级为账号事实。

排除：目录排序／时间戳、唯一数字目录、登录配置中的上次账号、联系人名称、群成员、
单独的文件句柄路径及单独的 MAC 成功。句柄能证明目标进程持有某文件，但不声明哪个
账号已登录；旧连接残留和多账号都需要独立的当前登录身份来排除。不能扫描其他账号
数据库寻找 MAC 命中，也不能重新接入 NapCat 来伪装解决。

## 二、“QQ 退出”前提保护的内容

`providers/qq_independent/snapshot.py::prepare` 是无 WAL 的关闭主库路径：
复制前后检查 QQ 退出、拒绝 WAL／SHM／journal，持有禁止写入的源句柄，复核句柄与路径
身份、完整长度及摘要。它同时排除既有写者、未合并提交、复制期间源替换／改变，以及
启动 QQ 引发新的数据库活动。仅删除进程检查无法令普通复制成为一致快照。

[SQLite 的 WAL 及锁协议](https://www.sqlite.org/walformat.html)说明活动状态跨 main、
WAL 和映射 SHM；已提交但未 checkpoint 的记录可只在 WAL。现有实现已经有替代保护：

- `source_guard.ps1` 只读打开 main／WAL／SHM，禁止删除替换，持有 Windows main
  SHARED、DMS、共享 checkpoint 与 reader 锁；不修改数据库或 read marks。
- checkpoint 锁保护 main；reader 锁阻止 WAL 重用。没有取得 writer 锁，允许追加提交，
  但 checkpoint 会在捕获期间受限；不能据此承诺真实 QQ 完全不受延迟影响。
- `main_wal.mjs::createMergedEncryptedDatabase` 固定提交边界 B，检查双 SHM 头、
  校验和、salt、页数、backfill／attempted，复核 main 内容和至 B 的完整 WAL 前缀。
  后续追加不扩展本次输出；变化、锁失败、取消、超时或见证不明均拒绝。
- 输出仍是加密副本。源锁及 helper 释放得到确认后，才能进入独立页 MAC／解密，
  再对自有明文做 SQLite 完整性检查；不调用旧桥接解密 API。

源锁保持现有最多 65 秒预算；原独立消费者仍有同步、120 秒和密钥作用域边界。
本轮没有改变它们、增加重试或扩展密钥存活时间。
未来接线必须共享现有整体剩余预算，不能给快照、各元数据库与认证分别重启计时再叠加。
这里的单库交叉验证也不证明三库具有跨库事务一致性或已经满足完整获取的总预算。

## 三、可行时序与尚缺的实际接线

后续活动获取须分开以下阶段，不能仅移动现有 `prepare` 调用：

1. 验证正常 QQ 进程代际及组件；只有未过期的真实 armed 才提示登录。
2. 收到单次目标响应，停止观察并确认 helper／在途调用状态。敏感材料只在原有有界内存中。
3. 取得独立、可信的当前登录身份及准确数据库位置，重新检查账号／进程代际；未知或冲突即停。
4. 对已绑定账号获取受锁保护的加密 main/WAL 快照；随后确认源锁与 helper 释放。
5. 在同步作用域内认证并解密，SQLite 校验通过后才提供会话列表与读取。
6. 消费／取消／失败后清理自有敏感副本和密钥，资源未知时禁止替换任务。

账号与登录代际须在获取前后保持一致；同一 PID／创建时间内的换号或重新登录不等于
同一登录代际，没有可信的转换／失效证据时不能用进程代际替代它。

当前 `connectOnce` 在启动前要求 5120 字节首页，loader 停止后立即调用同步认证消费者；
它没有“事件之后等待可信账号并异步冻结输入”的入口。`withAuthenticatedKey` 明确拒绝
异步 consumer。因此不能在回调中随意 await 捕获或把密钥带出作用域。账号证据成立后
仍需在认证前安排有界的加密捕获；本轮交叉验证只验证该先后顺序及格式，不伪造原生接线。

另需分别记录“数据／密钥已清理”和“原生组件完全卸载”。生产 `EchoStop` 关闭观察、
清零材料，但保留 trampoline／DLL，`connectOnce` 明确返回 `component_unloaded=false`。
只有所绑定 QQ 正常退出后的代际句柄证据才确认完全释放。活库复制不能改变这个事实，
不能自动关闭 QQ，也不能因报告成功放宽未知状态的后续任务／安装准入。

若实机不支持上述锁／SHM 方式，最小替代为：可信账号绑定 → 捕获并停止观察 → 提示用户
自行正常退出 QQ → 确认原代际退出 → 原关闭主库快照。该方案仍须有界内存等待、超时
清理和捕获协议适配，当前未实现；不能宣称已支持，也不能长期缓存密钥等待退出。

## 四、离线交叉验证

复用 `test_qq_direct_main_wal_acquisition.py` 与现有虚构编码器、SQLite 保留区 fixture：

- 分别以 48／80 字节保留区构造真实 SQLite WAL、独立 SHA1 页 MAC 的加密 main/WAL；
  使用现有源锁与合并器，不调用 `core`、`DatabaseApi` 或旧解密实现。
- 捕获 B 后追加一个校验有效的新提交。B 后的提交不进入输出，源锁释放之后才进入
  生产认证消费者，全部输出页认证通过，SQLite integrity_check 为 `ok`，读取仍为 B 的值。
- 80 字节格式另验取消及 WAL checksum 有效但页 MAC 错误：前者不能到认证消费者，
  后者必须是页 MAC 拒绝而非其他原因；无明文输出，损坏时临时明文删除得到确认。
- 成功／拒绝后均可重命名虚构源文件，验证没有 helper 残留的禁止删除句柄。
  这是实际 Windows 文件锁／子进程检查，不是实际 QQ 生命周期证据。

新增 4 个必要交叉场景；两份相关测试合计 **85 passed**。使用显式工作区解释器、当前
源码、固定现有 Node 和隔离用户目录。没有新增测试体系或更改生产捕获、认证及清理代码。

## 五、最小下一步与停止条件

尚缺一项真实证据组合：**同一正常 QQ 登录代际的当前账号声明，以及该声明到实际
数据库目录的独立关联**。历史账号输入、成员 UID/UIN 与取钥回执不能提供它。

需另行授权一次受限、只读的身份／路径与锁兼容验证，而不是重新研究取钥算法：
只允许当前授权账号，先验证登录身份来源、字段类型与同代关联，再核对该账号数据目录
和 main/WAL/SHM 状态。候选发送字段未经实证，不能预设成功或忽略账号类型。多账号、
残留连接、跨代、路径冲突、没有独立身份来源或释放不明时立即停止，不读其他账号。
该范围不包含读取聊天正文、解密或获取新的数据库密钥，也不应输出身份与路径清单；
回执只保留验证布尔值、候选／冲突计数及固定拒绝原因。

若可靠身份来源需要扩展原生观察边界，须在该授权中明确允许并先验证其 ABI，不能把
本轮的静态字段审核或自建数据验收当作已经允许／已经验证。当前不安排登录或实机操作。
账号来源和实际快照条件确认后，才能改正式获取时序、实现多会话 GUI 并申请最终验收。
