# QQ 54395 身份／活动锁单次元数据验证

接续 `c6a910d`，范围为负责人另行批准的本人当前账号、QQ 9.9.37-54395。
本记录不包含账号、路径、进程号、昵称或协议载荷；未批准取钥、解密、聊天读取或报告生成。

## 离线准备

复用现有 Echo 原生组件的安装／停止／私有传输和进程代际验证。新增的研究构建开关
`-IdentityMetadata` 不进入正式 runtime，不替换发行摘要或原取钥二进制。
默认构建仍为原接收观察器；研究构建改为发送函数元数据观察器，不编译接收载荷读取分支。

最小原生读取范围：

- 当前回调的 owner → task → request，读取有界命令名，只允许既有目标命令。
- 只对匹配命令读取 task 的 24 字节账号候选字符串、4 字节原始类型码。
- 候选值只接受不带前导零的最多 20 位 ASCII 数字，其他表示立即拒绝；不猜 UID 转换。
- 不读取 request 的载荷指针／向量或任何响应内容，不导入取钥解析和数据库消费者。
- 私有管道只传固定 36 字节元数据记录。外部汇总仅含计数、布尔值、类型码及固定原因。

固定 [QScope profile](https://github.com/sj817/QScope/blob/0ee1533bb18c4ebdd918c355de27c204209acb3e/collectors/qqnt-windows/profile.json)
只作为候选布局来源，未使用其实现或采集器。独立复核已安装模块的固定 SHA256、PE
异常表、函数前缀及两条语义引用，唯一定位发送函数 `[0x1c38208, 0x1c3852a)`。
静态资料的日志引用只是一段前缀；磁盘实际完整日志还包含 `data_size` 和 `custom_sig`。
精确定位使用完整字符串，不能把截断文本当作 NUL 结尾锚点。

MSVC 反汇编另证实该函数从 task `+0x50` 取 DWORD 到日志类型参数，task `+0x38`
进入字符串复制后传入账号参数。研究检查器核对对应指令流与固定镜像摘要。这只证明
字段传递，不证明运行账号、在线角色或全局枚举含义。

负责人已独立确认仍为先前授权本人账号。参考值只进入本次进程的短期私有环境／内存，
不写入命令行、配置、Git 或回执。候选必须逐字节匹配该独立 UIN 参考，才可将本次观测
值归于已知 UIN 命名空间；单纯数字形状、原始类型码或磁盘目录都不足以判定。
本次匹配不自动建立所有类型码的通用定义，也不自动提供产品所需的当前在线／登录代际声明。

## 账号路径与活动锁范围

只查询被验证 QQ 进程代际的文件句柄元数据；不扫描磁盘账号目录，不按排序、时间戳或
唯一数字目录选择。系统句柄表先按目标 PID 和 File 对象类型过滤；只复制零访问权限句柄，
只对 DISK 句柄获取路径，不读取文件内容，不使用 `NtQueryObject` 或任意进程内存扫描。
路径查询放在自有有界 helper；阻塞或超时即停，不处置 QQ。无法复制的 File 句柄、
无法分类的设备和无法解析的磁盘路径都拒绝，不能静默漏掉潜在的第二账号。
虚构进程中出现的 KSEC／CRYPT_PROVIDER 设备经 SDK 类型确认后单独排除；其他未知设备
保持拒绝。这是设备元数据查询，不查询对象名称、不读取设备内容。

只有进程持有的账号目录唯一、目录账号与已交叉核对的本人 UIN 一致、主库／WAL／SHM
均为正常本地文件时才尝试锁。出现第二账号、多个库位置、身份或路径冲突即拒绝，不读其库。
获取锁前后重新核对同代进程持有的目录；不将 PID／创建时间等同于登录代际。

复用正式 `acquireSourceGuard` 与现有 `checkpointWitness`，仅将后者导出用于受限观察。
锁探针不调用 main/WAL 合并、数据库读取、解密或完整性检查。
仅映射／验证 136 字节 SHM 见证，保持双头、校验和、提交边界和对象身份的既有检查。
本次申请锁预算最多 8 秒；helper 保留独立 TTL，结束必须确认释放应答和退出。
没有获得 writer 锁，不能承诺对真实 QQ 零延迟；锁／见证异常立即释放并停止。
这只能验证真实锁兼容与快照必要条件，不能宣称已完成真实活动全库快照。

## 单次操作与清理

离线准备和模块检查不启动／关闭 QQ。用户先正常打开 QQ 并停在登录页；实际 Ready 帧
才对应 `armed`，有界登录窗口最多 120 秒，过期不提示登录。启动生成排他的单次标记，
不自动重试，不提供更换账号／进程的交互。

取消／超时／失败后停止观察、清零原生暂存槽、关闭私有传输。所有自有 helper 归入
kill-on-close Job，QQ 从不加入该 Job。仅终止自有 helper，QQ 由负责人正常退出。
保留原 DLL／trampoline 策略：停止读取不等于组件卸载；绑定进程的 SYNCHRONIZE 句柄
确认正常代际退出后，才记录组件完全释放。本轮不产生密钥或数据库明文，不存在其落盘副本。
研究二进制、虚构库与编译产物仅在被忽略的 build 范围保留，不进入 Git。
历史被审核拒绝清理的目录不变。

### 离线复现与最小修复

使用自有虚构数据库进程调用系统 `D3D11CreateDevice`，独立创建／释放图形设备，
复现相同 `0x22` 拒绝：目标 File 句柄 25 个，复制 10 个即拒绝，数据库路径 0 个。
该样本与 QQ 拒绝类型相同，不能据此断言 QQ 中的具体对象就是同一图形设备。

进一步在自有样本中查询原生对象名称，只输出结构事实：它处于 `\Device` 命名空间、
只有设备端点两个名称组件、不含文件路径。设备名称本身不写日志或仓库，分类不依赖
固定驱动名。

修复仅限当前已出现的 `GetFileType=UNKNOWN` 且设备类型 `0x22`：在原有独立有界查询
helper 内调用元数据接口 [NtQueryObject](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/nf-ntifs-zwqueryobject)，
核对返回状态、缓冲区长度、UNICODE_STRING 指针范围和编码。只有成功确认是
`\Device\单个端点`、没有文件组件的原始设备句柄，才作为非普通数据库文件排除。
这是基于原生命名空间的分类，不是给所有未知类型或任意路径增加忽略项。

带文件组件的未知对象、其他命名空间、未命名、超长、错误缓冲区、查询失败及其他
未支持设备类型仍拒绝。实际数据库仍要求完整普通本地文件路径、唯一账号目录、独立
本人参考匹配和前后同代复核。对象名称只留在 helper 私有内存，外部仅有端点计数。
名字查询可能受驱动阻塞，沿用父任务 8 秒预算和自有 Job；未确认释放不能标为成功。

诊断同时增加有界 Win32 error／设备类型／NTSTATUS，并在每个句柄开始时清除旧值，
避免将前一对象的错误信息误归到后一对象。成功也保留计数；原生名称和路径不外发。
锁阶段只转发明确白名单拒绝码，不再将 SHM 检查失败全部折叠为通用错误。

此结果暴露出上一版诊断器范围过窄：已建立的对象角色校验只用于 `0x22`，其他合法

按编号直接排除的快捷分支。现在所有合法 UNKNOWN 返回都要经过相同的证据链：

1. `GetFileType=UNKNOWN` 且 Win32 error 为 0，排除 API 调用失败。
2. 设备元数据查询成功；查询失败不得继续猜测。
3. 有界原生名称查询成功，指针、长度及编码有效，明确是无文件组件的设备端点。

只有第三步确证的原始设备端点才排除；含文件路径、其他命名空间、未命名、查询失败
或无效返回仍拒绝。设备编号只用于脱敏诊断，不再控制准入。这不是逐个增加设备类型
忽略项，账号／数据库路径和前后代际校验不变，也不改变来源的普通本地文件合同。

自建进程新增零访问权限 NSI 句柄，仅打开／关闭设备，不查询网卡、地址、网络配置，
不发送网络流量；fixture 明确断言其 UNKNOWN 返回和设备类型 `18`，防止误把其他
对象当作覆盖。与自建 D3D 设备及虚构 WAL 库组合，全部句柄枚举、3 个数据库文件
发现、源锁和见证验证、前后复核及释放通过。设备端点计数随自有句柄数量变化，未将
固定句柄总数当作产品验收要求。

错账号仍在锁前拒绝，空 WAL 明确拒绝并确认释放；原元数据 18 项自检通过，未新增
大量重复测试。自有图形上下文、网络设备、数据库连接、句柄及所有 helper 已释放。
本轮没有再运行修复后的真实验证，未改 GUI、未构建 Frozen／Setup，两个产品前置
仍待实际目录绑定与活动锁证据，不能宣布完成。
