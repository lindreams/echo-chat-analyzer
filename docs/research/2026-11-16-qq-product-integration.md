# 独立 QQ 正式通路集成

本轮在研究分支上接续已验收成果；基线为 `3136950`。负责人批准代码修改、
必要回归、本地分批提交及候选构建，禁止新的真实 QQ 取钥、Hook、登录和聊天读取，
禁止修改 main、合并、推送或发布。本记录不包含账号、群、昵称、正文、原始响应或私有资产路径。

## 成果保护与复用

先审核未提交源码、测试与研究记录，并按明确文件名单保存。真实报告、媒体、实验目录、
配置和构建资产继续留在 Git 外；来源不明的现存目录不清理、不暂存。
研究期间的消息事实、表情目标优先级及词语回顾排序先保存为独立提交，
认证解密、元数据与实验记录另行保存。研究脚本随后委托同一生产组件，
保留虚构数据编码器和研究专用检查，不将实验 CLI 纳入产品入口。

已验证的原生登录事件、内存取钥、每库 KDF、48/80 字节页面认证、完整解密和
SQLite 校验直接复用。独立 JS 仅打包生产依赖。旧 main/WAL 模板保留已审核字节，
仅补齐研究期间短写及 close 错误处理对应的历史模板 pin；不恢复 NapCat 产品依赖。

## 正式用户流程

1. 选择 QQ.exe、当前账号的数字目录和一个授权群；可明确关闭媒体恢复。
2. 用户正常退出 QQ 后准备三库只读加密快照。存在 QQ 进程、辅助文件、错误版本、
   路径重解析、链接或不可靠输入时拒绝准备。
3. 用户自行打开 QQ 并停留在登录页，点击等待登录。只绑定明确镜像与创建时间的
   唯一主进程；待未过期的 armed 提示再登录。GUI 队列迟到提示也必须重新校验期限。
4. 内存认证取钥，逐页解密与 SQLite 检查；按稳定证据发现群分区，逐行严格复核。
   40030 明确匹配才接受；其为 0 时仅接受同一行 40021 明确匹配。其余情况拒绝。
5. 仅对授权群的稳定成员标识查询名称。Provider 正常排除须与已验证原生形态对账，
   未分类排除拒绝；不以原始行数等于报告消息数作为通过条件。
6. 复用 Provider、Adapter、统一过滤与 Analysis、媒体目标选择、PIC / MFACE 恢复和
   Report Package。账号窄缓存根仅在媒体开关开启时传递，不连接旧桥接服务。
7. 临时数据库及加密副本在 payload 物化后删除；payload 闲置十分钟或一次消费后清理。
   报告保存至原有 Catalog。用户正常退出 QQ，才能以原进程代际句柄确认 DLL 完全释放。

未知发送者和无名称证据者继续保持未知；不修改归属、名称优先级或分析统计。
微信业务链路未改；两个来源复用既有会话选择、日期范围、分析进度与报告界面。

## 生命周期与失败边界

准备至消费由独占 OS lease 覆盖，私有 ACL 先于敏感写入。仅清理身份绑定的本轮目录，
固定 allowlist 全部校验后删除，敏感文件先于 owner proof。未知文件拒删，删除失败保留
证明以便恢复。进程 Job、reader 或句柄释放未确认时保留 owner 和 lease，禁止新一轮覆盖。
取消不等于清理成功；关闭先封闭准入，再有界等待并报告失败或未知。

卸载的保留数据、清空数据两种选择均接入同一独立工作区 owner，活动 lease 或未知文件
保持失败关闭，不跟随账号目录或删除 QQ 原库。既有全来源更新准入的 UNKNOWN 约束保留。

## 离线证据

- 虚构账号、授权群与其他群哨兵覆盖正式 Facade → Provider → Adapter → Analysis → HTML。
  检查名称附加、一次性消费、消息排除对账、身份冲突拒绝、损坏 SQLite 拒绝和临时文件删除。
- 虚构本地 MFACE 动画经过账号可信根、正式媒体准备与报告发布，HTML 引用包内 GIF，
  导出文件可解码为两帧；测试禁止真实 CDN 与 QQ 访问。PIC 与 MFACE 的原生虚构全链检查沿用现有组件。
- 定向覆盖取消、窗口关闭时正在捕获、过期 armed、闲置清理、删除失败、Job 退出未确认、
  未知文件与卸载中的活动 lease。未确认资源不得制造释放成功。
- 原生虚构事件到完整报告检查通过，包含每库 KDF、完整性、严格群见证、过滤与时间口径、
  表达 / PIC / MFACE 事实、组件停止、自有进程树退出；明确不访问真实 QQ。
- Windows runtime / Setup / Portable 定向检查通过；无符号链接权限的节点按原条件跳过，
  不将其计为通过。桌面 Smoke 和既有 GUI、关闭协议回归通过。

测试使用显式工作区解释器、目标 src 与隔离用户目录。Windows 测试暂存路径过长会导致
媒体文件创建失败，改用短的本轮自有 basetemp 复验，不改变业务或弱化断言。
本机 jieba 数据缺失按固定官方版本和已核验摘要补齐，未更换依赖版本。

## 候选构建与待验收

生产 native DLL / loader 由现有 MSVC x64 构建，MinHook 固定修订及源码摘要不变。
固定产物与 Node 哈希受运行时及打包双重校验。生产包不含 fixture host、实验 DLL、
NapCat runtime、账号配置、密钥、聊天数据库或报告。许可随包携带。
原生构建带工具链相关身份，重新构建需单独审核新产物 pin，不能默认字节可复现。

使用固定版本 vpk、独立 lab 安装身份和新输出目录构建，不安装或覆盖正式版。
本机原配置 vpk 缺 vendor 文件；复用通过 NuGet 仓库签名验证的同版本包，
在本轮自有目录解出完整工具，未修改共享工具或系统 PATH。
Frozen 与 Setup 完整性验证不代替跨机器、真实账号、完整升级卸载与真人视觉验收。

最后仍需负责人另行批准一次正式 GUI QQ 验收：按上述受控顺序登录，复核本人／群归属、
消息和时间、名称覆盖、重点表情与动画、取消和正常退出后的组件释放。
不为补齐历史昵称、全部媒体或更多 QQ 版本无限扩展范围。
