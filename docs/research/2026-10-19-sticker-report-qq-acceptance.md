## 当前可运行边界

QQ 私聊、群聊已具备从 GUI 选择会话到统计报告的代码通路。
实际运行仍取决于用户手动连接成功、当前 QQ schema 可读、所选会话能取得合法快照。
本轮没有检查真实账号或本机 runtime 私有状态，不能证明上述条件已满足。

默认 GUI 分析不请求网络媒体，也不传入可信素材目录。因此可以生成带发送次数、
素材种类及排名的报告，但图片通常为空；这不是图片恢复成功。
此前缺口是素材窗口只更新自己的 `StickerData`。本轮已增加明确的
“保存素材到新报告”动作：恢复结果通过 Facade 和分析应用服务，复用保留的报告视图
及同一份发送事实装配 JSON/HTML，发布新的报告包并打开；旧报告保持不变。
保存不再读取聊天、不重新运行算法，也不额外获取媒体。未经用户点击保存，结果仍只在内存。

## 源码链路

1. `gui/session_analysis_panel.py::start_analysis` 将会话、时间范围交给
   `ChatAnalyzerFacade.analyze_session`，私聊和群聊共用入口。
2. Facade 的 `_analyze_direct_db_qq_session` 经 `_session_export_context` 调用
   `QQDirectDatabaseImportService.acquired_session`。同一 generation 定位会话、
   物化 `qq-db-json` 并取得会话类型；明文 DB 在交给分析前完成 cleanup，payload
   在消费结束后由 acquisition 清理。不另建来源读取或解析路径。
3. `ImportService` / `qq_db_adapter.py` 建立 RichMessage 与投影实例配对。
   `AnalysisApplicationService` 依次执行 scope、Smart Profile、质量过滤；
   `rich_by_instance` 只保留存活投影对应的 Rich 事实，重复消息 ID 不用于跨消息拼接。
4. `collect_sticker_sends` 收集确认发送，`count_sticker_messages` 使用同一 Rich 范围；
   `resolve_sticker_media` 生成媒体状态，构成 `StickerData`。没有可信 roots 不读文件。
5. `aggregate_stickers` 按来源、会话类型、会话 ID 隔离，计算材料、成员、完整排名及
   实验招牌证据。未知素材身份计入发送量，不冒充同一素材，不参与素材归并排名。
6. `AnalysisReports.stickers` → `build_echo_report_view` → `build_echo_stickers` →
   `EchoStickers` → serializer → JSON / 内嵌同一展示数据的 HTML → 报告包。
   JSON 是展示快照，不是可重新分析的原始聊天。

### 四种证据必须分开

| 层次 | 当前依据与边界 |
| --- | --- |
| 确认发送 | QQ PIC 只接受明确的 `45003=1` 自定义表情标志；普通图片不猜成表情包。MarketFace 需要 type 11 的有效 `45600` bytes。 |
| 可靠归并 | PIC 使用 `45406` 内容 MD5；缺失时保留未知发送。MarketFace 使用原始 bytes 的 SHA-256 不透明身份，只证明相同来源 bytes，不证明已解码的资源摘要；两种命名空间不互相归并。 |
| 原件或可信预览 | 本地恢复要求授权根目录、完整 MD5、完整图片解码、安全预算均通过。QQ 获取先复核唯一消息与 PIC 元素；取回 bytes 摘要一致为 `available`，不一致但来源映射可信为 `preview`，不得冒充原件。MarketFace 缺少已证明的原件摘要，当前恢复不支持。 |
| 报告实际图片 | 只接受 `available` / `preview` 且带有效 bytes 的 PNG/APNG、JPEG、GIF、WebP。仅装配展示选中的各成员 Top 10、招牌及满足展示条件的共同榜、群总榜，去重后共享 16 MiB 原始 bytes 预算；不是恢复全部素材。Base64 会扩大导出体积。 |

报告保留所有可靠成员的候选展示数据，即使群聊当前只选中一名成员；图片选择不只限于
页面最初可见的 Top 3。资源缺失、预算省略或浏览器加载失败不改变统计次数。
报告所需目标由 `sticker_report_targets` 从同一展示模型生成；Top 10 展开范围、
招牌、共同榜与群总榜取并集，按可靠 media key 去重。QQ 素材窗口只列这些目标，
使用与报告相同的“素材 NN”标号；本地关联仍按每页最多 32 种，网络仍逐项确认。
素材窗口保留完整发送事实，不把统计范围裁成恢复目标范围。

`assets` 现保留每个目标的状态及固定原因分类。`available` / `preview` 且具有
非空 `data_uri` 才表示实际装配的图片；其他状态的 URI 为空。可区分未请求、
缺失、映射失败、其他失败、不支持、取消及预算受限，报告预算原因为
`report_asset_budget`。失败重试不会覆盖先前已验证的有效图片。

## 耗时观测

复用 `analysis_diagnostics.timed_stage`，新增日志只含固定阶段名称和整数毫秒。
不记录聊天正文、账号、素材身份、路径、凭据或 bytes。计时补充在应用层，
没有修改 Provider、Adapter、认证、快照与媒体授权合同。

| 环节 | 现有或本轮补充的阶段 |
| --- | --- |
| 会话获取（现有） | `direct_db_acquisition` 分列 snapshot、lookup、materialize、cleanup、metadata、member、enrich 毫秒；`facade_acquisition` 记录外层获取。 |
| 统计（补充细分） | `sticker_data` 包含事实收集及媒体状态处理；`sticker_media_resolve` 单列媒体解析/校验；`sticker_aggregation` 单列聚合、排名及招牌证据。 |
| 本地恢复（补充） | `sticker_directory_discovery` 为用户主动触发的目录发现；`sticker_media_associate` 为授权页关联。GUI 已有候选数、读取数、遍历完整性、预算及失败状态。 |
| QQ 单项恢复（补充） | `sticker_media_download` 为已通过校验后的下载调用；`sticker_media_verify` 为 bytes 摘要与解码校验。不包含此前消息重读、内核映射及人工确认时间。 |
| 装配/导出（补充） | `report_view_assets` 含视图选择及表情包 Base64 装配；`report_json_export`、`report_html_export`、`report_package` 分开记录。HTML 阶段还含其他内置表达和品牌资源装配。 |
| 总体（现有） | `total` 是分析服务总耗时，不含来源获取和包发布；`facade_analysis` 包含核心分析与包发布，不含来源获取及退出 acquisition 后的 payload 清理。 |
| 媒体重导出（本轮） | `sticker_report_export` 包含资源重装配、JSON/HTML 写入及新包发布，内部复用上述三个导出计时及 `report_package`。不含用户授权、媒体恢复及浏览器启动。 |

这些计时存在嵌套，不能把所有日志毫秒直接相加。`timed_stage` 在异常退出也记耗时，
出现计时行不代表成功；结合 GUI 结果、素材状态和公开错误分类判断。
从点击“开始分析”到报告可见另记墙钟时间，包括 GUI 排队及浏览器启动。
尚无真实数据速度结果，不给出预计秒数。

源码启动的现有诊断日志位置为仓库内 `Echo/logs/echo.log`；不要上传整份日志。
只在本机查看所需阶段、数量和失败类别。计时沿用 INFO 日志级别，可通过将
`qq_chat_analyzer.desktop.analysis_diagnostics` logger 调为 WARNING 关闭；默认 GUI
没有新增设置项。其他既有来源诊断日志不受这个 logger 的开关控制。

## 回来后的最短流程

1. 在仓库根目录手动启动本轮源码，避免启动旧安装版：

   ```powershell
   $env:PYTHONPATH = (Resolve-Path .\src).Path
   & .\.venv\Scripts\python.exe -m qq_chat_analyzer.gui
   ```

   你本人完成连接 QQ 和登录。连接失败先保留公开错误，不绕过来源校验。
2. 选择一段已知有表情包的真实私聊，限定适量日期范围并生成报告，记录墙钟时间。
   核对第 06 章、我/TA 归属、Top 3/Top 10、未知身份提示；人工对照同范围内少量
   QQ 发送记录。次数按内容出现次数，一条消息可以多次发送；最终统计会受过滤影响。
   短范围没有招牌是正常结果，不能据此判定失败。
3. 选择一个真实群聊重复生成；核对全群榜、成员切换、逐成员发送及未知归属。
   共同素材不足三种时只有种类数、没有共同排行榜，是当前展示规则。
4. 打开“查看表情素材”只查看已有事实和状态，不点任何恢复按钮；记录下表。
   报告 JSON 的 `stickers` 对象提供前三项数值；统计 `assets` 中非空 `data_uri`
   才是装配的独特图片数，`assets` 总长度是需要展示的目标数。
   `available` 表示章节可展示，不能当作“全部图片可用”。
5. 经你明确确认后，每种会话先选 1–3 项高频 QQ PIC，逐项点“通过 QQ 获取所选素材”
   并确认。群聊选择一条对应成员的发送记录，尽量含自己及其他成员。记录墙钟时间、
   `available` / `preview` / 失败类别、动画是否正确；结果先在当前窗口内存。
   MFACE 不适用此获取入口。不同会话重新生成后，旧素材窗口和内存结果会关闭。
6. 点击“保存素材到新报告”，确认自动打开的新 HTML 有原件或明确标注的可信预览，
   原报告不变。断网重开新报告确认资源自包含；不要把素材窗口预览代替报告验收。
   恢复失败时也可保存已尝试的状态，统计仍应一致。根据少量实测再决定是否扩大。
   需要本地恢复时另行确认目录范围后，才使用
   “关联本页原件（最多32种）”；该按钮不能只关联本页选中的一项，首次少量验收
   不应误用它代替单项获取。不要预先批量恢复、扫描其他私人目录或上传聊天。
