# PIC-1：QQ PIC 字段对照实验

这是离线诊断入口，不是 QQ 获取、导出或媒体恢复功能。它不改正式 PIC 分类、
MD5 冲突保护、Snapshot、认证或 Sticker 数据契约，不接触 MFACE。
本阶段仅有虚构数据验证；当前 Windows QQ 字段含义和原图恢复均未实测。

## 人工准备（尚未替用户执行）

1. 固定并自行记录 Windows QQ 和 Echo 版本。在无隐私的测试会话中选择少量消息：
   同一 PNG 分别用普通图片和自定义表情方式发送，一个多帧 GIF 自定义表情重复发送，
   再发送一个不同素材。按实际发送方式记录标签，不能根据字段反推标签。
2. 仅从用户已明确授权获取的现役 Provider payload 中，手工选择这些消息的
   `records[*].message_blob`。它是包含 `40800` 元素的完整 Base64 容器，
   不能用某一个内层 PIC 段或整份 payload 替代。不要拷贝正文、成员、会话或账号字段。
   本探针不会获取数据库，也不会为取样而延长 Snapshot / 临时 payload 生命周期。
   若尚无可用的已授权消息体，应先停在样本准备阶段，不能绕过获取策略自行取钥或扫库。
3. 在仓库外创建独立实验目录，只放选定的图片副本及以下清单。
   原图与缩略图可分别列入，但须自行记录哪个副本是什么版本；不要修改真实缓存。
   清单必须逐文件列名，不接受目录、通配符、绝对路径或越界路径。
   消息携带的路径不提供读取权限，也不会被探针跟随。
4. 原始清单、消息体、真实素材以及本机版本/样本对照笔记均保留在本机，勿提交或上传。

清单格式（把占位符替换为所选消息体，补齐所有样本）：

```json
{
  "samples": [
    {"message_blob": "<Base64 container>", "pic_index": 0, "known_class": "ordinary"},
    {"message_blob": "<Base64 container>", "pic_index": 0, "known_class": "custom"}
  ],
  "media": ["png-original.copy", "gif-original.copy", "thumbnail.copy"]
}
```

`pic_index` 从零开始，只计该消息的 PIC 元素；混合消息应准确选择目标段。
`known_class` 只接受 `ordinary`、`custom`、`unknown`，是人工标签，不是探针认定。
允许 `media: []`，此时仅作字段观察，不读取任何媒体。
媒体名相对于显式传入的素材目录，子目录仅使用 `/` 分隔。

## 手动运行

从目标工作树启动，使用 DEVELOPMENT 已验证的源码环境。以下实验路径仅为示例，
由用户换成自己明确授权的目录；不得改成整个账号缓存根。

```powershell
$EchoPython = (Resolve-Path .\.venv\Scripts\python.exe).Path
$env:PYTHONPATH = (Resolve-Path .\src).Path
& $EchoPython .\scripts\qq_pic_probe.py --input D:\EchoPic1Selected\selected.json --media-root D:\EchoPic1Selected\copies
```

成功输出一个 JSON 对象，退出码为 0；输入或全局预算错误输出固定错误码，退出码为 2。
错误不会附带路径、输入值或 traceback。个别素材缺失、不可读、非法图片或安全拒绝会
在对应 `mN` 下明确标注；不能将退出码 0 理解为所有素材成功。

## 如何读结果

- `s1` 等按清单样本顺序，`m1` 等按媒体清单顺序；均不输出用户提供的名字。
- `45003 / 45416 / 45418`：记录存在性、wire type、有限范围内的数值；
  类型异常或范围外仅输出类别。`45403 / 45812` 仅记录路径线索存在，不输出或读取路径。
- `45406 / 45424`：独立记录原始 16 字节 MD5、32 字符十六进制候选或无效值，
  不输出完整摘要。`dN` 是本次运行内部的摘要相等关系，不是持久素材身份。
  重复字段逐项显示；冲突或错误类型使两字段关系不可比较。
- `matches`：对清单中实际读取的完整文件计算 MD5 后匹配的 `mN`，不按名称或扩展名匹配。
  空列表只表示所选副本中没有匹配，不代表整个缓存不存在。
  只有相应媒体同时为 `valid_image`，才能认定所选文件通过了图片验证。
  格式和帧数来自实际解码，不取首帧、不改写文件。
- `digest_relation` 为 `different` 且 `both_digests_match_valid_images=true`，
  证明本次两个摘要各自匹配了合法图片。仍需人工来源对照才能说明哪个是原图、缩略图或其他版本。
- `production_digest` 展示现役 Adapter 是否仍保留摘要，诊断独立比较不放宽其冲突保护。
- `classification_comparison` 最多为 `separates_selected_labels_only`，只说明所选人工标签
  被观察值分开；也可能为重叠或证据不足。不能据此发布通用分类规则。
- `napcat`、`pic_subtype_mapping` 固定为 `not_observed`：现役已认证接口没有可复用的
  PIC 原生元素查询入口，本探针不增加 RPC、读取凭据或调用下载。
- `original_association` 固定为 `not_established`：摘要匹配和图片可解码不自动证明
  它是该消息原图。需要人工确认副本来源、版本以及对应摘要字段，之后再审核后续实现。

## 资源和安全边界

最多 16 个样本、16 个明确文件；清单不超过 2 MiB，每消息体不超过 64 KiB；
每媒体不超过 16 MiB，总读取媒体不超过 64 MiB。每张图片最多累计 8M 像素、32 帧，
媒体阶段有 10 秒协作式预算（不是可强制终止底层 I/O/解码的硬超时）。
复用正式媒体模块的安全文件打开、重解析点拒绝、读取稳定性和完整帧解码验证。
无目录枚举、默认路径、联网、解混淆或文件写入。拒绝 UNC、路径越界、链接及 JSON 重复键。

## 本阶段的验收结论

虚构测试验证了字段观察、摘要相等关系、重复 GIF、不同素材、双摘要不同但均匹配合法图片、
缺失/错误类型/非法媒体、安全拒绝和脱敏输出。这些样本中 `45003` 的数值由测试人工构造，
不构成当前 QQ 与 `picSubType` 等价的证据。

真实小样本运行后，应逐项人工记录：两个发送方式是否确实不同、重复素材是否相同、
各摘要实际匹配的副本版本、多帧是否完整，以及无法匹配的项目。即使全部通过，
结论也仅覆盖记录的客户端版本和样本；没有原生对照就继续标记 `picSubType` 未验证。
完成后交人工审核，本阶段不修改正式规则。
