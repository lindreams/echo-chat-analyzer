# 大规模数据优化记录

基线：`203ed0a8231517e98d0e0cdb223fce89aca2677a`。本轮仅做局部优化，
不改变统计、QQ 身份、快照准入、媒体完整性或单在途合同。

## 1. Direct DB payload 只写出一次

原实现：SQLite → records → JSON 写盘 → 清理快照 → 元数据请求 →
JSON 全量读回 → 补充身份 → JSON 再写盘。现在在 provider 中共用
`read_session_payload` 构造原始数据，Direct DB 服务在清理快照后原位补充身份，
只写最终 JSON。现有文件导入接口和独立 materialize 接口保持不变。
原始 records 不复制；服务在交给 ImportService 前释放 payload 引用。

## 2. Node 快照与媒体诊断日志轮转

Python `echo.log` 已有 5 MiB × 当前文件及 3 份备份的轮转，本轮不重复实现。
Node 的 snapshot/bridge 原有 6 处直接 append，没有大小或保留上限；现在共用
同一个诊断写入函数，使用相同的 5 MiB / 3 份策略，保留所有既有固定字段、
阶段耗时、失败原因和代码指纹。新增模板已纳入 pins 和两份运行时清单。
未更新本机 runtime，也未构建发行产物。

定向检查覆盖首次轮转完整保留超过 5 MiB 的旧文件、连续写入 24 MiB 后只保留
当前文件与 3 份备份、模拟 Windows EPERM 时继续记录且备份不被删除、
锁解除后恢复轮转、日志路径不可写时不影响业务。正常固定长度记录的稳态上限
约 20 MiB；既有超大日志及持续锁定是例外，不能承诺严格硬限。
旧日志首次保留原始大小，之后按正常保留策略到期；轮转失败没有 unlink/truncate
兜底。收益是限制长期磁盘占用，没有据此宣称分析耗时改善或内存降低。
快照 Node 集成测试 `test_qq_direct_db_snapshot_runtime.py`：36 passed。
桥接测试夹具同步为完整插件布局，身份验证和拒绝外部绑定的断言不变。

验证中发现独立环境限制：当前虚拟环境安装的 Echo 元数据版本为 0.3.1，
基线 pyproject 声明为 0.3.3。`test_spec_excludes_unused_jieba_data_and_local_install_provenance`
因此在版本保护处失败；相关源码、spec、pyproject 本轮均未修改。
不为让测试通过而弱化保护或修改安装环境，构建验收留项。

## 3. 本次报告复用完整的本地缓存目录清单

原实现每 32 个 PIC 目标重新遍历相同缓存目录。现在每份报告在本地阶段共用
一个完整目录清单，阶段结束即释放；只缓存路径候选，不缓存授权或已验证原件。
根目录、授权 scopes、深度和遍历预算必须完全一致，每批仍检查根目录和 scopes，
每个候选仍完整执行现有路径/句柄见证、全文件 MD5、冲突检测、完整图片解码。
32 项批次的字节/解码预算、128 MiB 保留上限、取消和 QQ 单在途均保持不变。
没有设置素材总数上限，没有修改 QQ RPC 或放宽任何原件判定。

只有完整遍历能发布清单；超时、取消、不安全目录等失败不会发布部分清单。
`scan_reused` 诊断标识区分复用；复用时 entries/files 是首次完整清单的计数。
本地目录在首次遍历后新增的文件留待原生 QQ 获取或下一次分析发现。
本次清单不会扩大读权限，实际读文件时重新执行完整校验，文件替换仍会被检测。
