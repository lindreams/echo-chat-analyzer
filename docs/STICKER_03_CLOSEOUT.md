### QQ 跨机器解密反馈修复（2026-10-26）

一份候选跨机器日志在快照与输入稳定性校验通过后返回 `decrypt_failed`；
原日志将解密异常、输出缺失及输出校验失败合并，不能据此确认实际密钥或数据库格式问题。
虚构数据复现了错误／空密钥也被视为就绪、随后输出校验失败的同类现象。

本轮调整密钥捕获补丁，忽略空值而不覆盖已有有效值；修复源数据库状态诊断的 API 接收者丢失。
解密调用、输出缺失、文件形态与头部校验分别记录固定脱敏阶段／错误码，不记录密钥、正文或路径。
仅解密返回拒绝或头部校验失败且暂存清理成功时，允许重新捕获；此类失败最多三次尝试，
与快照不稳定恢复共用既有 65 秒预算和六次总尝试上限。
权限／未知调用异常、输出缺失、文件形态异常、身份变化与清理失败不进入此恢复。
所有既有快照一致性、身份、所有权及 SQLite 完整性准入继续保留，错误输出不发布。

README 同步当前正式版下载入口、待发布表情包能力和日志反馈方式。
本轮候选与原候选分开保留；源码和安装包验证结果另行留证，目标故障机器仍需复测。
本轮修复不构成正式发布或原故障根因已被确认。

### QQ 诊断覆盖补齐（2026-10-26）

为减少跨机器反复补日志，在原有两份本地日志中补齐以下固定字段：

- Echo／Python／Windows 构建与实际 QQ 版本，桥接、登录、数据库 API、密钥存在及快照 API 就绪状态。
- 解密输出的字节数、期望页数、SQLite 签名／页大小／格式版本／页数校验布尔值；
  权限、磁盘满、文件占用、原生加载与已知加密错误只映射到固定分类。
- 身份前后变化、manifest 写入和验证、原子发布、加密中间文件清理的具体失败阶段；
  请求超时或断连后丢弃结果及其清理结果写入诊断文件，避免只留在被丢弃的 stderr。
- 重试决策、剩余预算与停止原因；导入／范围筛选／过滤／有效文本／分词数量、
  群聊语言样本资格数量，以及分析或导出失败的具体阶段。

新增字段不包含正文、词语、成员标识、密钥值／摘要或本机绝对路径；不改变身份和完整性准入。
反馈仍只需同次运行的 `echo.log` 与 `qq-snapshot-diagnostics.log` 及发生时间、操作步骤，
无需聊天数据库或额外调试启动参数。故障注入与产物验证只使用虚构数据；
这些诊断能区分已覆盖的失败分支，不承诺外部原生组件的所有未知故障都能直接确定根因。

新增故障注入、QQ／Smoke、分析与日志回归以及新候选 Frozen 资源合同均已通过；
Windows 符号链接权限用例跳过，默认 dist 不存在的原生 PE 检查另行对实际候选执行。
新包已验证隔离用户目录、清空开发环境、中文空格移位路径下的原生启动退出，
以及独立实验身份的安装／卸载、虚构用户数据保留；原有安装注册和快捷方式保持原样。
