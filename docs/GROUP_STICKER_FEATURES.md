# 群聊表情特色首版

本页描述当前源码，不构成真实数据、跨机器或发行验收通过。
算法只消费正式过滤后、同一来源同一群聊的 Rich 配对；不新增数据库查询、
群成员历史、图片理解、情绪或关系评分。所有“首次”“没有使用”“群内”均限定在本段可见记录。

## 链路与证据

`AnalysisApplicationService` 在媒体恢复前，复用 `aggregate_stickers` 与
`build_sticker_fact_index(..., conversation_kind="group")`，返回
`result.reports.group_stickers`。私聊与群聊分析入口分开，互不套用规则。
群聊只要求可靠发送者身份，不要求每人具备 `is_self`；同名成员不合并。
缺少单一会话范围时不输出。未知时间、未知素材和未知成员保持未知，不摊给任何人。

微信当前数据库入口只查询文字与 Type 47 表情，不包含完整图片、语音、系统消息或回复历史。
索引能保留导入后的过滤／配对缺口，不能发现来源查询之前省略的记录；因此接龙只描述
本段可见投影里的接续，不证明原始群聊没有其他消息。当前成员名也不证明历史入群日期。

证据及原始关系引用留在本机进程内。Presentation 仅投影称谓、日期、计数、
窗口分母和既有资源的 `asset_key`，沿用 `echo-report.v0.10` 的 `sticker_memories`。
不通用序列化证据对象，不导出消息正文、账号、消息引用或素材身份 key。

## 八类资格

阈值用于筛出值得阅读的观察，不表示统计显著性、人格或社交影响力。

| 类别 | 输出条件与限制 |
| --- | --- |
| 同图接龙 | 连续至少四个作者轮、至少三名可靠成员使用同一可靠素材；连续同作者消息先合轮，轮间间隔最多 120 秒、整段最多 600 秒。文字轮无该图、未知身份／素材／时间、同秒、时间倒退及过滤缺口均中断。每种素材保留最长合格窗口，不把刷屏次数当人数。 |
| 群内使用变化 | 比较相邻两个 28 天窗口；按每 28 天边界及记录末端检查。高峰至少五次、跨两天、两人使用；另一窗至少十次可辨认表情，两窗均至少两名实际发表情成员。素材占比至少三倍变化且相差至少十个百分点。报告展示两个窗口的发送分母；使用人数与同期发表情人数保留在本地证据中。成员构成会影响占比，不声称成员偏好发生因果变化。 |
| 旧图重逢 | 此前至少两人、三天、五次使用；再次出现与前次相隔至少 28 天且达到此前日间隔中位数的三倍。间隔内至少十次其他可辨认表情、三个活跃日；过滤缺口或任意成员的相关未知素材均阻止“未见使用”判断。回归当天只一人用时明确显示一人。每图保留间隔最长的合格观察。 |
| 成员独特偏爱 | 先满足既有招牌合同：四次、四天、28 天跨度、四个活跃周、占个人可辨认发送至少 10%。还需至少两名其他发表情成员、其他成员至少十次可辨认发送。个人与其他成员的平滑占比比值至少三倍；使用加一平滑避免无穷比值，未知量过大时不输出。不再额外要求十五个百分点绝对差，避免漏掉符合持续使用资格的低占比偏爱。不是“独家拥有”或招牌次数榜。 |
| 长期群内习惯 | 同图至少三名成员各自满足既有持续使用合同；报告给出各人次数、天数、首末日期，同期实际发表情人数保留在本地证据中。只描述可见记录中的长期复用，不称为全体群员共识。 |
| 使用圈扩大 | 至少三名成员各自三次、跨两天且占个人可辨认发送至少 10%；首次可见日期至少分成两天。时间不明、可能遮蔽先前使用的未知素材、过滤缺口或来源顺序矛盾时不输出。按日期展示，同日不推断先后；不称首创、带动或传播因果。 |
| 等量风格差异 | 仅比较至少十次可辨认发送、跨两天且个人素材可辨认比例至少 80% 的成员；整段发送可可靠归属的比例也须至少 80%。不足样本或识别覆盖率低的成员在计算共同样本量之前排除，不能拉低全群样本。所有合格成员使用相同样本量，最多一百次。复用私聊的无放回预计种类数，展示两端；丰富度比至少 1.8、差至少三种、有效种类数 D2 比至少 1.5。覆盖率门槛是保守的展示质量要求，不证明未知素材随机缺失，也不推算未知种类或全量动图偏好。 |
| QQ 明确引用附图 | 仅 QQ 已解析的唯一 ReplyRelation，目标必须仍在同次保留群聊集合，双方身份可靠、不同人，目标在前且时间严格较早，当前消息含可靠表情。仅说明“明确回复并附图”；不从相邻发送或未解析 @ 推断互动，不导出被回复内容。微信当前来源没有相应关系事实，因此不输出这一类。 |

日期按 Asia/Shanghai；时间窗口右端不包含。趋势占比分母为有可靠成员及素材身份、
时间可用的发送，参与人数分母为同期有时间可用发送的可靠成员；两者不是名义群人数。
观察到的过滤缺口保留为屏障。只有已有来源事实能独立证明被删行都是普通文字时，
才允许清除表情计数缺口，仍不清除接龙连续性屏障。

## 组织与展示

同一素材的事件与长期背景合成一条故事；保留完整合格算法结果，展示时每图每类
通常取一条，独特偏爱至多三人。先按发现强弱排序，再给合格类别留位置并填其他素材；最多九条故事，
前三条重点、其余紧凑，不保证每份记录都出现八类。
强弱沿用私聊的编辑标准：至少十二轮接龙、至少 180 天重逢、至少五十个百分点变化或
至少一年持续偏爱优先；八轮以上接龙或同图有多类补充事实次之。并列时先看类别丰富度，
再用素材身份稳定打破平局，不使用图片恢复结果参与精选。
这属于首版启发式精选，不是全体成员两两比较或传播网络。

复用私聊的章内回忆、趋势窗、日期、风格图和接龙模板。群聊采用可靠显示名或
不含账号的成员编号，重名消歧；接龙预览最多十二轮，共同习惯和使用圈日期最多展示六人，
保留总人数及必要的截断提示。长昵称换行。紧凑故事保留附属发现的标题、日期与比较数值。
报告只展示结果，不附带筛选阈值、计算口径、其他成员对照分母或招牌挑选依据；
这些解释留在本设计文档中。等量风格的估计数值用“约”标示。

基础全群榜、共同榜和分档成员榜继续使用既有口径，展开后统一为单行横向滚动，
各榜独立展开／收起。共同榜有一项即展示，不因不足三种素材而伪报空记录。
群聊回忆素材加入同一去重目标集合，
本地恢复、QQ 获取和离线报告复用该集合及既有验证边界；是否有图不影响算法资格或精选。
缺图显示占位，不替换证据、不回读聊天来源。

## 验证边界

虚构数据覆盖八类正例，以及单人刷屏、同秒、断序、缺口、未知素材、跨来源、
唯一引用、稀疏成员、媒体失败不影响资格、跨会话投影拒绝与分享证据隔离。
QQ／微信正式 Adapter 到应用服务及导出链均有回归；桌面 Chromium 覆盖
复用模板、全类别摘要、长昵称、缺图及无横向溢出。

诊断复用既有日志，在 `[group-sticker-counts]` 中记录每类资格、固定原因淘汰数及精选数量，
在 `[group-sticker-projection-counts]` 中记录范围匹配与投影数量。仅包含固定字段及整数，
不含账号、素材身份、原文或路径；用于区分无合格候选、精选和展示问题，不进入分享报告。

负责人已反馈此前本机验收完成，主要剩余跨机器验收。这不能自动覆盖新增群聊算法；
新增发现仍需小群／大群真实记录复核阅读价值与误判，跨机器及最终 Frozen／Setup
结果单独记录。当前测试与交付状态见 [收尾汇总](STICKER_03_CLOSEOUT.md)。
